# 安全政策

本文档说明 Career Skills Marketplace 的安全规范以及如何报告安全漏洞。

---

## API 密钥管理

**API 密钥及任何凭证不得提交到 git 仓库。**

- 所有密钥、token、secret 必须通过环境变量或本地 `.env` 文件传入，`.env` 文件已列入 `.gitignore`，不得手动从 `.gitignore` 移除。
- 如果在历史提交中意外包含了密钥，需立即轮换该密钥，并联系仓库维护者清理 git 历史。
- CI/CD 中的密钥通过平台 Secret 管理功能注入，不写入任何配置文件。

---

## 用户数据保护

**用户的简历、个人信息及求职记录不得上传到任何外部系统。**

- 所有用户数据仅在本地处理，不写入本仓库的任何文件。
- `.evidence/` 目录已列入 `.gitignore`，该目录下的所有内容（包括中间处理结果）不得提交。
- 贡献者不得将真实用户的简历、求职材料用作测试数据；示例数据必须为明确虚构的内容。
- Skill 在执行过程中不得将用户输入持久化到本地文件之外的位置（如远程日志、第三方分析服务）。

---

## .gitignore 要求

以下路径必须始终保持在 `.gitignore` 中，维护者会在 PR 审查时检查：

```
.env
.env.*
*.key
*.pem
*.p12
.evidence/
```

任何试图从 `.gitignore` 中移除上述条目的 PR 将被拒绝。

---

## 报告安全漏洞

如果你发现安全漏洞（包括数据泄露风险、依赖包高危 CVE、逻辑缺陷等），请按以下方式报告：

1. **不要**在 GitHub Issues 或公开频道中披露漏洞细节。
2. 通过电子邮件将漏洞描述发送至维护者邮箱（联系方式见仓库 README 底部）。
3. 邮件主题格式：`[SECURITY] <简短描述>`。
4. 在邮件中说明：漏洞类型、影响范围、复现步骤（如可提供）。
5. 维护者将在 **3 个工作日** 内确认收到，并在 **14 个工作日** 内给出处理方案。
6. 漏洞修复发布后，经报告者同意，可在更新日志中致谢。

---

## 依赖安全

- 依赖包版本锁定在 lock 文件中，不接受宽泛版本范围（如 `*` 或 `>=x`）的新依赖。
- 维护者定期运行依赖漏洞扫描，发现高危 CVE 时优先处理。
- 贡献者新增依赖时，需在 PR 描述中说明用途及来源可信度。
