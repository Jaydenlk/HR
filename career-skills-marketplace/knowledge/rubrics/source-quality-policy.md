# 数据来源质量政策（Source Quality Policy）

## 概述

本政策规定Career Skills Marketplace插件在使用薪资数据、公司信息、面试经验等外部信息时的质量评级、新鲜度要求、冲突解决规则和引用格式。

---

## 第一部分：平台质量分级

### A级来源（高可信，优先使用）

| 来源 | 类型 | 适用数据 | 可信度说明 |
|------|------|---------|-----------|
| 官方财报/招股书 | 一手资料 | 营收、员工数、业务线 | 法律合规，数据准确 |
| 脉脉（Maimai）薪资 | 匿名社区 | 真实薪资（样本>20条） | 样本量够时可信，可能偏高估 |
| 领英（LinkedIn）职位 | 职场平台 | 岗位需求、技能要求 | 正式发布，信息相对规范 |
| Boss直聘发布薪资 | 招聘平台 | 薪资区间 | 通常为谈判区间，非最终数字 |
| 公司官方博客/公告 | 一手资料 | 产品线、战略方向、招聘方向 | 可能有PR包装，用于方向判断 |

**使用规则：** A级来源直接使用，标注来源和时间。

---

### B级来源（中等可信，需结合多个来源交叉验证）

| 来源 | 类型 | 适用数据 | 局限性 |
|------|------|---------|--------|
| 牛客网求职社区 | UGC内容 | 面试经历、薪资（应届生） | 主要反映应届生数据，社招参考价值有限 |
| 知乎职场话题 | 问答社区 | 行业认知、公司文化 | 个体经验为主，有偏差 |
| 应届生求职论坛 | 垂直社区 | 校招流程、开奖数据 | 局限于应届生群体 |
| 看准网（Kanzhun/Glassdoor中国版） | 匿名评价 | 公司文化、管理评价 | 愤怒离职员工占比高，有负面偏差 |
| 人脉内推/朋友反馈 | 一手口头 | 团队氛围、真实薪资 | 个体经验，样本量=1 |

**使用规则：** B级来源需注明"参考来源"，不可单独作为结论依据，需与其他来源交叉验证。

---

### C级来源（低可信，仅用于辅助参考，不可直接引用）

| 来源 | 局限性 |
|------|--------|
| 自媒体文章（公众号/头条）| 可能有利益输送，数据未经核实 |
| 二手转述（"我听说XX公司给30K"）| 无可核实路径 |
| 超过18个月的薪资数据 | 市场变化快，过时数据可能误导 |
| 未注明样本量的薪资统计 | 极少数样本可能极度偏离均值 |
| 匿名帖子中的极端值（最高/最低）| 可能是正常分布的尾部，不代表普遍情况 |

**使用规则：** C级来源只能作为"另一种可能性"列出，必须标注"低可信度，仅供参考"，不可作为推荐建议的依据。

---

## 第二部分：新鲜度要求

### 数据有效期规则

| 数据类型 | 建议有效期 | 过期处理方式 |
|----------|-----------|-------------|
| 薪资区间 | 6个月 | 超期数据加注"可能已过时"，建议重新核实 |
| 公司面试风格 | 12个月 | 面试官和业务变化快，超期需说明可能已调整 |
| 公司业务线 | 12个月 | 互联网公司业务调整频繁，需核实 |
| 公司文化评价 | 18个月 | 文化相对稳定，但换管理层后需重新评估 |
| 岗位要求（技术栈）| 6个月 | 技术生态变化快，超期可能与现实脱节 |
| 公司行业地位 | 24个月 | 相对稳定，但赛道变化剧烈时需更新 |

### 时效性标注格式

每条使用外部数据的建议必须包含时间标注：

```
格式：[来源类型] [采集时间] [可信度]
示例：[脉脉薪资样本，2026年Q1，N=34条] base范围 28-35K
示例：[知乎问答，2025年6月，参考] 该公司面试分4轮
```

## 第三部分：冲突解决规则

### 当多个来源数据冲突时的处理优先级

**规则一：级别高者优先**

A级来源数据与B级来源冲突时，采用A级数据，并说明B级来源存在的版本。

**规则二：新鲜度优先**

同级来源中，时间更近者优先（相差超过6个月视为显著差异）。

**规则三：样本量优先**

同级同时间来源中，样本量更大者优先（如脉脉100条样本优于5条样本）。

**规则四：区间保守原则**

当薪资数据来源存在冲突且无法确定优先级时，使用较低的数字作为"保底参考"，提醒用户实际可能更高或更低。

**规则五：明确存疑，不强行合并**

若来源冲突且无法解决，直接告知用户：

```
"关于该公司薪资，存在两种不同数据来源：
- 来源A（脉脉，2026-Q1）：base 30-38K
- 来源B（牛客，2025-Q3）：base 25-32K
建议在面试过程中直接向HR确认。"
```

## 第四部分：引用格式规范

### 在给用户的建议中引用外部数据的格式

**薪资数据引用：**

```
参考薪资（仅供框架使用）：base 25-35K/月
数据来源：脉脉匿名薪资（2026年Q1，约30条样本）
注：实际薪资受个人经验、绩效表现、谈判能力影响，以实际offer为准。
```

**面试经验引用：**

```
面试风格参考（2025年下半年数据）：
来源：牛客/应届生论坛整合（约15条经历）
第一轮：算法题（LeetCode中等）
第二轮：系统设计（分布式场景）
注：面试官和题目会随时间变化，以上仅供准备参考。
```

**公司信息引用：**

```
公司信息来源：官网/官方博客/公开报道（截至2026年Q2）
稳定性：如公司有近期融资/裁员新闻，请参考最新公开信息核实。
```

---

## 第五部分：禁止使用情形

插件在以下情况下不得引用外部数据，应明确告知用户信息不足：

1. **无可靠来源时**：不推测或编造薪资、面试数据，直接说明"暂无可靠数据，建议通过脉脉/内推了解"

2. **数据过时且无更新时**：超过24个月的所有薪资数据一律不引用，转而提供查询建议

3. **仅有单一极端案例时**：单个样本的极端值（如某人拿到SP offer）不可作为普遍参考

4. **政策敏感信息时**：国企/政府岗位的内部晋升机制、薪资结构等，因保密性强，无法核实的不引用

## 第六部分：数据更新策略

### 知识库刷新周期

| 数据类别 | 目标刷新频率 | 触发条件 |
|----------|------------|---------|
| 薪资基准 | 每季度 | 市场重大变化（裁员潮/涨薪潮）时即时更新 |
| 公司基本信息 | 每半年 | 公司重大事件（上市/倒闭/并购）时即时更新 |
| 面试风格 | 每年 | 大规模校招后更新（秋招/春招结束后） |
| 术语表 | 按需更新 | 新术语出现时增量更新 |

### 置信度声明

所有插件输出中，涉及外部数据的结论必须包含以下免责声明格式：

```
以上信息基于公开数据和社区样本（{来源描述}），仅供参考框架使用。
实际情况可能因公司业务变化、个人背景差异和市场行情波动而有所不同。
建议通过内推人脉、HR直接沟通获取最新信息后再做决策。
```
