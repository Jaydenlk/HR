# JD解析规则（Job Description Parsing Rubric）

## 概述

本规则用于从招聘JD中系统性提取显性需求和隐性需求，识别风险信号，解析薪资结构，帮助求职者做出更准确的岗位评估和简历针对性优化。

---

## 第一部分：需求提取框架

### 显性需求（Explicit Requirements）

显性需求是JD中直接明确描述的内容，通常出现在"任职要求"或"岗位要求"部分。

**提取方法：**

1. **学历要求**
   - 最低学历限制（本科/硕士/博士）
   - 专业限制（计算机/统计/商科等）
   - 院校偏好（985/211/一本）——注意：直接写明"985优先"是歧视性描述，但实际存在于部分JD

2. **技术栈要求**
   - 必须掌握（"熟练掌握"/"精通"）
   - 加分项（"有XX经验者优先"）
   - 区分强制要求和可替代技能

3. **工作年限**
   - 严格要求（"3年以上后端经验"）
   - 灵活要求（"优秀应届生可接受"）

4. **证书/资质**
   - 法定类（医师执照/律师证/会计师证）
   - 加分类（CPA/CFA/PMP）
   - 过期/特定版本的证书注意核实

**提取示例：**

```
原文："具备2年以上Python开发经验，熟悉Django/FastAPI框架，有大数据处理经验（Spark/Hive）者优先"

解析结果：
- 强制：Python，2年以上，Django或FastAPI
- 加分：Spark或Hive（大数据方向）
- 灵活项：框架可任选其一
```

---

### 隐性需求（Implicit Requirements）

隐性需求是JD文字背后隐藏的实际偏好，往往比显性需求更重要。

**常见隐性需求识别方法：**

**1. 从业务描述推断技术深度**

| JD描述 | 实际隐性需求 |
|--------|-------------|
| "高并发/高可用系统" | 分布式系统架构经验，QPS万级以上实战 |
| "用户千万级产品" | 大规模数据处理，A/B测试经验 |
| "0到1搭建" | 技术选型能力，从无到有的工程能力 |
| "与海外团队协作" | 英语沟通能力，实际非装饰性要求 |

**2. 从公司类型推断文化适配**

| 公司类型 | 隐性文化要求 |
|----------|-------------|
| 互联网大厂 | 接受快节奏、996弹性、OKR结果导向 |
| 外企 | 英语工作能力、合规意识、层级汇报规范 |
| 初创公司 | 极强执行力、接受角色模糊、对不确定性耐受 |
| 国企/央企 | 政治敏感度、尊重层级、接受慢节奏 |

**3. 从用词推断真实要求**

| 用词 | 实际含义 |
|------|---------|
| "优先考虑大厂背景" | 非大厂背景可能会在初筛被过滤 |
| "有创业经验者优先" | 期望接受低薪+期权的工作方式 |
| "能承受工作压力" | 加班文化较重 |
| "参与多项目并行" | 同时背负多个项目KPI |
| "职业发展空间大" | 短期薪资可能偏低 |

## 第二部分：风险信号识别

### 高风险信号（需主动询问或谨慎对待）

**红旗一：薪资描述不透明**
- 表现：只写"薪资面议"或区间极大（如"10-50K"）
- 风险：实际可能在区间下沿，面议对求职者不利
- 应对：第一轮电话沟通即明确薪资预期，避免浪费多轮面试

**红旗二：用工形式不明确**
- 表现：JD未明确标注是否为外包/OD/劳务派遣
- 风险：入职后发现与目标公司非直接劳动关系
- 识别方法：注意发布方是否为第三方人力公司，HR邮箱后缀是否与目标公司一致
- 应对：第一轮面试前直接询问"请问该岗位合同签署方是XX公司吗？"

**红旗三：岗位描述与实际业务脱节**
- 表现：产品岗描述中没有具体业务线或用户规模描述
- 风险：实际可能是边缘业务或新成立的探索部门
- 应对：搜索该公司该业务线的公开信息，面试时询问团队规模和业务阶段

**红旗四：招聘时间过长**
- 表现：同一JD持续3个月以上招聘
- 风险：HC可能被冻结但JD未下架，或岗位要求极高导致持续招人
- 应对：直接询问该岗位目前是否有HC，已面试多少人

**红旗五：职位名称与薪资不匹配**
- 表现："资深工程师"薪资却在初级市场范围内
- 风险：公司薪资体系整体偏低，或为降本控费导致
- 应对：用市场数据（如脉脉薪资、Boss直聘行情）比对

**中风险信号（需关注）：**

- 试用期超过3个月（法定为1-6个月，试用期薪资可低于正式薪资）
- 要求"服从调度/轮岗"（可能意味着岗位不稳定）
- 描述中出现"弹性工作制"但实际文化是高强度

## 第三部分：薪资结构解析

### 中国职场薪资结构拆解

**标准总包公式：**

```
年总包 = base月薪 × 发薪月数 + 年终奖 + RSU/期权（若有）
```

**发薪月数说明：**

| 发薪月数 | 实际含义 | 常见公司类型 |
|----------|---------|-------------|
| 12薪 | 只发12个月base，奖金另计 | 部分传统企业 |
| 13薪 | 年底多发1个月 | 外企、快消常见 |
| 14-15薪 | 结合节日/年终奖 | 互联网中厂常见 |
| 16薪 | 较优厚，年终约4个月 | 互联网大厂（阿里/腾讯/字节基准） |
| 18薪+ | 行业顶配，含较大绩效奖金 | 大厂高级岗位 |

**注意：** JD中描述的"16薪"通常是"base×16"的固定部分，年终奖按绩效发放不包含在内。

**年终奖结构类型：**

| 类型 | 特点 | 风险 |
|------|------|------|
| 固定年终奖 | 按月数发放，与绩效关联弱 | 低，但总额通常不高 |
| 绩效年终奖 | 完全依赖绩效评定 | 中，绩效评级影响大（S/A/B/C） |
| 利润分红 | 与公司/部门营收挂钩 | 高，受市场行情影响 |
| 项目奖金 | 与特定项目成功挂钩 | 高，项目失败则无 |

**RSU/期权解析：**

- RSU（限制性股票单元）：归属期通常4年，年度解锁，归属时按市价或约定价兑现
- 期权：有行权价，股价高于行权价才有收益，上市前价值不确定
- 关键问题：
  - 归属计划（Vesting Schedule）：1年悬崖期（cliff）后每月/季/年解锁多少？
  - 估值方式：按最后一轮融资估值还是上市后市价？
  - 离职处理：提前离职期权是否作废？保留期限多长？

**五险一金计算：**

- 养老保险：个人8%，单位16-20%
- 医疗保险：个人2%，单位约8-10%
- 失业保险：个人0.5%，单位0.5-1%
- 工伤/生育保险：单位全额承担
- 住房公积金：个人5-12%，单位等额匹配（比例因城市和企业不同）
- 注意：缴纳基数是否按实际工资（大厂通常全额），还是按最低基数（部分中小公司压低五险一金节省成本）

## 第四部分：中国平台格式差异

### 不同招聘平台的JD风格差异

**Boss直聘（BOSS Zhipin）**
- 特点：JD相对简短，侧重突出薪资吸引力
- 解析重点：薪资区间通常是谈判起点，非最终数字；"随时沟通"的BOSS模式适合主动询问
- 隐患：外包岗位混入，需仔细辨别发布方

**智联招聘/前程无忧（51job）**
- 特点：传统格式，JD较为详细，多用于传统行业、外企、国企
- 解析重点：福利描述比Boss更详细，但薪资描述常含"面议"
- 关注：发布时间（超过30天未更新的JD可能HC已满）

**猎聘（Liepin）**
- 特点：面向3年以上有经验候选人，猎头发布为主
- 解析重点：猎头发布的JD部分信息经过包装，需直接询问真实情况
- 隐患：同一岗位可能有多个猎头发布，造成信息混乱

**领英（LinkedIn）**
- 特点：外企和出海公司使用频率高，英文JD为主
- 解析重点：英文JD中"nice to have"vs"required"的区分比中文JD更清晰

**脉脉（Maimai）**
- 特点：内推优先，职场社交属性强
- 解析重点：可通过脉脉查询该公司内部八卦和文化，辅助JD评估
- 优势：内推候选人通过率显著高于投递渠道

**校招专用平台（牛客/应届生求职）**
- 特点：面向应届生，笔试/面试流程标准化
- 解析重点：校招JD常不写薪资区间，需主动询问或参考往年开奖数据

## 综合解析清单

解析一份JD时，依次完成以下检查：

- [ ] 提取显性技能要求，标注强制/加分
- [ ] 识别隐性文化信号
- [ ] 核实发布方是否为目标公司（非外包）
- [ ] 检查薪资描述，拆分base/奖金/股票
- [ ] 扫描红旗信号（任何一条红旗需在面试前确认）
- [ ] 对比岗位要求与自身简历匹配度（>70%再投递效率最高）
