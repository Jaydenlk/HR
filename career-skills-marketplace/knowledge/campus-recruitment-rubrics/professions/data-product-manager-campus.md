# 数据产品经理（数据产品经理 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`data-product-manager-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 指标体系与数据建模能力（口径治理×维度建模）（满分 28）
- **好的样子**：能讲清一套指标从无到有怎么搭：原子指标→派生指标→指标字典/统一口径，对标阿里 OneData（业务域/数据域/业务过程/度量/维度/修饰词/时间周期/派生指标）那套方法论说得出名词且用对。维度建模有真懂：星型/雪花模型、事实表与维度表区分、缓慢变化维(SCD)、数仓分层(ODS/DWD/DWS/ADS)能讲清每层放什么、为什么分层(减少重复计算、统一口径、提升下游开发效率)。简历里有真实做过的指标体系/数仓主题搭建项目:为某业务从 0 到 1 梳理核心指标、统一了哪些口径不一致、用维度建模抽象出了哪些事实/维度逻辑表。区别于数据分析师的关键就在这里——交付的是指标字典和模型,不是一份分析报告。
- **应届证据**：在项目/实习经历里写明:为 [业务线] 搭建指标体系,梳理 X 个原子/派生指标并沉淀指标字典统一口径;或参与数仓主题建模,在 DWD/DWS 层抽象出 X 张事实表/维度表。出现「指标口径」「指标字典」「维度建模」「星型模型」「数仓分层」「OneData」等术语且绑定自己做的具体动作,而非空背概念。课程项目/竞赛(如数据建模、BI 大赛)做过指标设计或维度建模亦可佐证。
- **常见缺失 / 反模式**：把「会看数据」「做过几张报表」当成有指标体系能力,简历里全是分析结论却零口径治理、零建模;或维度建模、数仓分层只在技能栏堆名词,问到「为什么要分 DWD 和 DWS」「事实表和维度表怎么区分」就答不上。【反模式·口径裱糊匠:满嘴指标体系、数据中台,真问起原子指标和派生指标怎么拆、口径不一致怎么治理就支吾,概念背得溜实操一片空白,面试官一戳就破】

### 2. SQL 与数据取数实操能力（硬门槛×真实佐证）（满分 24）
- **好的样子**：SQL 是数据 PM 的「人手必备」硬门槛,校招笔试直接考:增删改查、分组聚合、多表 JOIN、子查询、窗口函数(row_number/rank/sum over)必须实操过而非「了解」。简历里 SQL 绑定真实场景——用 SQL 自己取数验证指标口径、做过留存/漏斗/同环比的取数逻辑、在 Hive/MySQL 上跑过查询。Python(pandas 清洗/简单分析)、Excel 透视为加分门槛能力。每项工具都能对应一个「用它取了什么数、算了什么指标」的具体场景,而不是裸列一栏「精通 SQL/Python」。数据 PM 不必像数仓开发那样写复杂 ETL,但必须能独立取数、看懂数据、验证口径。
- **应届证据**：在项目/实习描述里写「用 SQL 完成 [留存率/漏斗转化/同环比] 的取数与口径验证」「用 Python(pandas)清洗 X 万行数据并产出 [指标]」,工具与产出绑定出现。技能栏可补充牛客/LeetCode SQL 刷题或大厂 SQL 笔试通过经历作为佐证,但正文必须有真实使用场景支撑。
- **常见缺失 / 反模式**：技能栏写「精通 SQL」「熟练 Python」,正文却找不到一个用它取数/算指标的项目,笔试一道窗口函数就现形;或只会在 BI 工具里拖拽,从没自己写过一行 SQL 验证口径。【反模式·精通牌取数侠:技能栏 SQL/Python 全标「精通」,正文零取数场景,真坐下来手写一道带窗口函数的留存 SQL 就卡壳,这是数据岗笔试第一刀】

### 3. 数据产品/数据相关实习与项目（岗位实质×端到端产出）（满分 24）
- **好的样子**：有真实的数据产品/数据方向实习或硬核项目,任务实质清晰:做过数据看板/BI 报表需求设计(从业务问题→指标拆解→看板原型→上线)、参与指标平台/数据中台/埋点系统的需求分析与功能设计、设计过埋点方案(事件/参数/上报口径)、参与数据治理/数据质量监控(DQC)规则配置。能体现端到端数据流向认知:从埋点采集→ETL 清洗→指标加工→可视化应用,自己在哪一环做了什么、解决了什么业务问题、带来什么量化结果(看板覆盖 X 个业务方、取数效率提升 X%、口径统一减少 X 个重复指标)。岗位实质优先于公司名气:大厂数据中台/BI/数据产品组实习最佳,中小厂真做过完整数据产品需求亦可。
- **应届证据**：实习/项目栏写明机构+数据相关部门(数据产品/数据中台/BI/增长数据)+起止时间,每段用 2-3 条 bullet 描述具体数据产品任务与可量化产出(设计了覆盖 X 业务的 Y 个核心指标看板、推动埋点方案落地 X 个事件),并交代「为什么做」(业务背景/解决什么问题),而非一句「参与数据相关工作」。
- **常见缺失 / 反模式**：拿纯数据分析实习(只产出分析报告、写周报看数)或通用产品实习(只画原型、做竞品)往数据 PM 上靠,以为「沾数据」「沾产品」就够;或项目只有流水账「负责数据看板」却讲不出指标怎么拆、埋点怎么设计、解决了什么。【反模式·画看板侠:实习经历全是「制作日报周报」「维护数据看板」,从没设计过指标、没碰过埋点和数仓,本质是个取数工具人,套个产品壳就来投数据 PM,录用官第一刀就砍这个】【反模式·报告搬运工:把数据分析师那套「分析 XX 原因、给出 XX 建议」原样搬来,通篇是结论没有产品设计,数据 PM 要的是搭工具定口径,不是写分析报告】

### 4. 数据平台与技术架构理解（中台×治理×血缘）（满分 14）
- **好的样子**：能用产品语言体现对数据基础设施的认知:数据中台五层(数据集成→加工 ETL→资产/数仓→服务→应用)、数据资产产品(数据地图、血缘、指标系统、质量监控 DQC)、数据治理(口径治理、数据安全/权限、成本优化)、常见技术栈认知(Hive/Spark/Flink/Kafka 大数据生态、DataWorks/DataX 等平台工具——理解其定位即可,无需会开发)。数据 PM 是「业务与工程之间的翻译」,既要懂业务也要能跟数据开发对话,所以技术理解是必备而非加分。哪怕是「实习中理解了数据从埋点到看板的完整链路」「调研过 DataWorks 的指标建模能力」也胜过完全无架构认知。
- **应届证据**：在实习/项目/课程描述中出现数据中台、数据血缘、数据地图、DQC、数仓分层、Hive/Spark/Flink、DataWorks 等关键词,并说明自己在其中理解了什么、用它对接了什么需求,而非纯名词罗列。能画出或讲清一条「数据从采集到应用」的链路是强信号。
- **常见缺失 / 反模式**：简历从头到尾只有 BI 看板和分析结论,完全不出现任何数据架构、中台、治理、血缘术语,显示只会用工具不懂底层,跟数据开发对不上话;或技术名词堆一排却讲不出 Hive 和 Flink 分别解决什么问题。【反模式·中台名词侠:简历里数据中台、数据血缘、湖仓一体名词堆满屏,真问「数据中台到底解决什么问题」「血缘有什么用」就只会复述定义,跟工程师一对话就露馅】

### 5. 学历背景与产品思维（专业匹配×需求逻辑）（满分 10）
- **好的样子**：本/硕为计算机、软件、数学统计、信息管理、数据科学等方向匹配度最高;经管/电商等专业需用 SQL+数据项目补足。院校越好越占隐形筛选优势(大厂数据中台核心岗对 985/211 偏好明显)。产品思维有真东西:项目描述能讲清「为什么做(业务背景)→怎么拆解(指标/需求)→怎么落地(方案设计)→结果(量化)」的完整逻辑,而非堆功能。数据 PM 的产品思维落点在「用数据/工具解决业务问题」,不是炫原型——能体现需求分析、口径对齐、跨团队推动(拉数据开发+业务方对齐口径)即为强信号。附 GPA 及数据相关核心课(数据库、数据结构、统计学、机器学习导论)成绩为佳。
- **应届证据**：教育背景栏写明院校+专业(标注数据/计算机/统计方向)+全日制+预计毕业时间,附 GPA;在项目描述中体现「业务背景→指标/需求拆解→方案→量化结果」的产品逻辑闭环,出现「需求分析」「跨团队对齐口径」「推动落地」等动作。
- **常见缺失 / 反模式**：把全部篇幅堆在 GPA、课程分数和无关学生工作上,零数据项目零 SQL,对数据 PM 而言仍是零竞争力;或项目通篇罗列「做了 A、做了 B」的功能流水账,讲不出「为什么做」和「解决什么业务问题」,暴露无产品思维。【反模式·绩点画原型侠:以为 GPA 拉满+几张漂亮原型图就能进数据 PM,简历里除了成绩单和界面图没有一个指标、一行 SQL、一段数据链路,录用官看的是数据硬功和业务逻辑不是颜值】

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度的 why 必须落到简历事实,按以下结构展开,分数与 why 严格一致:

① 命中/缺失事实(写进 evidenceFound / gap):
- metrics_system_modeling:evidenceFound 写出做过的指标体系/建模动作(如「为增长业务梳理 12 个核心指标并沉淀指标字典」「在 DWD 层抽象出 X 张事实表」);gap 写「全文只有分析结论无任何口径治理/建模」或「维度建模、数仓分层仅在技能栏堆名词无实操」。
- sql_data_skills:evidenceFound 写出 SQL/Python 绑定的取数场景(如「用 SQL 含窗口函数完成留存率取数」);gap 写「技能栏标精通 SQL 但正文零取数场景」。
- data_pm_internship_projects:evidenceFound 写出数据产品岗位实质与量化产出(如「字节数据中台组,设计覆盖 5 业务方的指标看板」);gap 写「仅有纯分析实习/通用产品实习无数据产品岗经历」或「项目只有『维护看板』无指标/埋点设计实质」。
- data_platform_understanding:evidenceFound 写命中的架构认知及参与内容(如「理解从埋点到看板的完整数据链路」「调研过 DataWorks 指标建模」);gap 写「全文无中台/血缘/数仓/Hive 等任何架构术语」。
- education_pm_thinking:evidenceFound 写院校+专业方向+GPA+产品逻辑闭环;gap 写「专业为经管且无 SQL 无数据项目补足」或「项目全是功能流水账无『为什么做』」。

② 校招语境下为何重要:必须说明该维度在数据 PM 校招的实际筛选作用——指标体系与建模是区别于数据分析师、数据 PM 立身之本(交付指标字典而非报告),分量最重;SQL 是笔试硬门槛(零佐证笔试即出局);数据产品/数据相关实习是录用官实际筛选第一位且不可被纯分析实习或通用产品实习替代;数据平台理解是「业务与工程翻译」的必备地基;学历与产品思维是隐形筛选线与逻辑闭环的体现。

③ 命中反模式直接点名:若命中则直呼「口径裱糊匠」「精通牌取数侠」「画看板侠」「报告搬运工」「中台名词侠」「绩点画原型侠」等,不得空泛说「有待提升」。

分数对齐:metrics_system_modeling 零口径治理零建模封顶不及格(数据 PM 核心能力缺失);sql_data_skills SQL 无任何佐证只能算缺失(笔试硬门槛);data_pm_internship_projects 仅有纯分析/通用产品实习不得给中等以上分(不可替代数据产品岗经历);data_platform_understanding 零架构术语给低分但不一票否决(属地基铺垫维度);education_pm_thinking 功能流水账无产品逻辑给低分。

严禁在 why 中出现「满分的 X%」「给分不超过」「故给满分」「扣 X 分」等内部比例话术,why 只陈述简历事实、反模式命中与校招筛选逻辑。

## 改写指引（禁编造铁律）
严格遵循「禁编造」干净句式,绝不替候选人添加原句没有体现的能力、技术名词或岗位实质:

1. 把简历「已有」的数据产品实习/项目句讲精准:明确写出解决什么业务问题(为什么做)、做了什么数据产品动作(梳理指标/搭建指标字典/设计埋点方案/设计看板/配置 DQC 规则)、用了什么方法(维度建模/SQL 取数/口径对齐)、量级多大(覆盖 X 个业务方、统一 X 个口径、X 个指标、提效 X%)。
   - 例:原句「负责数据看板」→ 改「为 [原文业务线] 设计核心指标看板,梳理 [原文已提及的指标] 并对齐取数口径,覆盖 [具体数字] 个业务方」(业务线、指标均须取自原文,缺则留占位或走 gap_advice)。

2. 用精准动词替换模糊词,但不得越级:原文写「协助/参与」就保留「参与」,严禁夸大为「独立负责/主导搭建」;原文确写了独立产出才可用「独立完成」。

3. 只在缺数字处用 [具体数字] 占位:如「梳理了 [具体数字] 个核心指标」「看板覆盖 [具体数字] 个业务方」「取数效率提升 [具体数字]%」,让候选人自行填真实数字,绝不代填。

4. 严禁编造能力:简历没写过 SQL/Python/维度建模/某数据平台/某监管或治理框架,一律不得在改写中添加;没体现过的指标体系搭建、埋点设计、数仓分层认知不得凭空生成;绝不把纯分析实习粉饰成「数据产品」、把通用 PM 原型经历伪装成数据建模。

5. 凡简历缺失的关键能力(如无指标/建模、无 SQL 佐证、无数据产品实习、无平台架构认知),一律走 gap_advice 给「建议补充」而非在 rewrite 里编造:
   - gap_advice 示例:「建议补充一段真实的指标体系搭建或维度建模经历,写明梳理了哪些指标、如何统一口径」「建议补充 SQL 的实际取数场景(如用窗口函数算留存率)而非仅在技能栏标注」「建议补充一段数据产品/数据中台/BI 方向实习并写明岗位实质」「建议补充对数据中台或数据链路(埋点→ETL→指标→可视化)的认知体现」「建议在项目中补全『为什么做』的业务背景与量化结果」。

## 本土惯例与硬规则
出局级硬规则:
- SQL 零佐证(技能栏写了却全文无任何取数场景,且无刷题/笔试通过记录):大厂数据岗校招笔试直接考 SQL,无 SQL 实操几乎笔试即出局。
- 无任何数据相关实习或硬核数据项目(指标/建模/埋点/看板设计):大厂数据中台/数据产品核心岗几乎不进面,因为无法判断岗位胜任。
- 纯数据分析实习冒充数据产品经历、通用 PM 原型经历伪装成数据建模:背调与面试追问即穿帮,数据 PM 看的是搭工具定口径不是写报告画原型。
- 简历虚假信息:大厂通过背景调查与笔试现场核验,造假一旦发现进入企业黑名单。
- 非全日制学历 / 无法按时拿到毕业证+学位证双证:大厂校招正式编制硬性出局。

硬技能/能力优先级(数据 PM 校招明确共识):
1. SQL(增删改查/JOIN/聚合/窗口函数)— 人手必备硬门槛,笔试必考,优先级最高。
2. 指标体系与维度建模(指标字典/口径治理/星型模型/数仓分层/OneData 方法论)— 区别于数据分析师的立身之本。
3. 数据产品岗位实质经历(指标看板设计/埋点方案/数据中台需求/DQC)— 录用官筛选第一位。
4. 数据平台与架构理解(中台/血缘/Hive·Spark·Flink 定位/DataWorks)— 跟工程师对话的地基。
5. Python(pandas)、BI 工具(Tableau/QuickBI/Superset)、Excel — 门槛加分能力。

明确反信号:把 CET、驾照、与数据无关的学生会经历当卖点堆首屏;技能栏全标「精通」正文零佐证;只会拖拽 BI 工具从不写 SQL。

格式偏好:
- 互联网大厂走网申系统,简历本科 1 页、研究生最多 2 页,首屏必须可见 SQL/数据项目/数据实习三件套。
- 项目经历严格按 STAR(情境-任务-行动-结果)写,每条带量化结果(覆盖 X 业务方/X 个指标/提效 X%),拒绝「取得良好效果」式主观形容。
- 投递大厂校招专项计划(字节 Top Seed、阿里星 Lab、美团北斗、腾讯青云)者,数据硬功与产品逻辑闭环须在首屏突出。

加分项(数据 PM 特有):
- 阿里 OneData / 数据中台相关实战项目或认证。
- 数据建模大赛、BI 大赛、Kaggle、数学建模国奖等可佐证数据硬功的竞赛。
- 牛客/LeetCode SQL 高频刷题或大厂 SQL 笔试通过记录(SQL 实操硬证据)。
- 完整的端到端数据产品案例(从埋点采集到指标看板上线的全链路参与)。
- DataWorks/Hive/Flink 等平台工具的真实使用或调研经历。

反信号(数据 PM 特有):
- 通篇分析结论、零口径治理零建模(分析师画皮)。
