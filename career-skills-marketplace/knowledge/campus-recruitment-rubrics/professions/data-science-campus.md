# 数据科学（数据科学 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`data-science-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 建模与统计基本功（满分 28）
- **好的样子**：项目中写明模型选型依据(为何选 LightGBM 而非逻辑回归、为何用树模型而非深度模型),并用 AUC/KS/GAUC/F1 等正确指标而非准确率评估;能从公式层面解释模型行为(GBDT 与 XGBoost 的差异、正则化作用、SHAP 特征归因),不均衡样本不用准确率衡量;数学/统计专业背景或手推过损失函数、贝叶斯公式的经历是加分。
- **应届证据**：建模项目里出现模型选型理由 + 评估指标(AUC/KS/GAUC)而非孤零零的“准确率 99%”;技术博客或论文里有损失函数推导/SHAP 分析;数学、统计、概率论、随机过程类课程结合项目实践;面经常考 XGBoost 损失推导、AUC 计算、正则化原理。
- **常见缺失 / 反模式**：技能栏堆满 XGBoost/LSTM/Transformer/BERT,却说不清为何选这个模型、答不出 XGBoost 与 GBDT 的区别、不知道超参数含义【反模式·调包侠:框架名背得溜、损失函数推不出】;项目只写“准确率 99%”不提样本比例、数据规模、是否数据泄露,对不均衡问题仍用准确率【反模式·准确率幻觉:指标选错,模型好坏无从判断】。

### 2. 特征工程与脏数据处理（满分 22）
- **好的样子**：能从原始日志/真实业务数据中构造有效特征(用户行为序列特征、时间窗口统计特征、类别变量目标编码),而非用泰坦尼克这类玩具数据集;说得清数据清洗挑战(缺失率、样本不均衡处理策略、异常值处理);有“从原始日志到特征宽表”的完整链路经验;竞赛排名注明百分比(天池/Kaggle 前 10%-20% 才有说服力)。
- **应届证据**：实习/项目里出现具体特征构造方式与数据清洗细节(缺失率多少、如何处理不均衡);有端到端取数→特征工程的链路描述;天池/Kaggle 竞赛写清排名百分比(前 X%)与特征方案;接触过真实业务量级数据(XX 万行/XX 亿条日志)。
- **常见缺失 / 反模式**：把泰坦尼克、股票预测等烂大街公开数据集包装成“工业级建模项目”,特征全是默认参数、模型 pip install 后复制粘贴,一问数据清洗与上线就崩【反模式·Kaggle搬运工:玩具数据集冒充真实战场】;只写“做了特征工程”却说不出造了哪些特征、为何这么造。

### 3. AB实验设计与因果推断（满分 22）
- **好的样子**：理解 p 值/置信区间/样本量背后的含义而非背公式,能设计可信 AB 实验(分桶分流、指标选取、显著性检验、上线决策),知道比值指标(CTR/CVR)的统计检验方法、规避辛普森悖论与样本比例失调(SRM)、了解 CUPED 降方差;具备超越“预测”的因果思维——做过 Uplift 模型(营销/增长场景,写明 ITE/HTE 目标与 AUUC 评估)或 Double ML/DID/PSM,能说清为何要识别混淆因子(confounders)。
- **应届证据**：实习中参与过完整 AB 流程并能说清结论与局限;简历出现 CUPED、分层抽样、显著性检验等进阶概念;因果项目写明 Uplift/AUUC/DID/PSM 方法与场景;概率统计/计量经济学课程结合实际应用;面经常考“CTR/CVR 比值指标怎么做检验”“方差太大检验不显著怎么办”。
- **常见缺失 / 反模式**：直接抛出“提升 X%”却没有置信度、样本量,问到实验设计就卡壳【反模式·结论党:数字有了、统计有效性为零】;建模只做离线验证,从不考虑特征延迟、线上线下一致性、数据分布漂移、模型监控,写“AUC=0.87”却答不出“上线后 QPS、延迟多少”【反模式·离线成功主义:实验室里赢、生产环境一上就崩】。

### 4. SQL与编程落地能力（满分 16）
- **好的样子**：能独立取数:复杂窗口函数、多表关联(面试现场白板写 SQL);Python(pandas/numpy)独立完成数据处理,熟练 sklearn/LightGBM/PyTorch 建模;有模型上线/部署经历(哪怕只是离线预测 pipeline)是加分;熟悉 Linux 命令行、能看 GPU 训练日志,不完全依赖数据工程团队就能把模型落地。
- **应届证据**：技能栏分层标注 SQL 熟练度、Python 数据/建模库,并有项目支撑;GitHub 有可查代码仓库(含 README、代码、结论);经历里出现“独立取数→建模→离线 pipeline”的端到端动作;美团等面经高频考 SQL 窗口函数、Linux/GPU 训练日志查看。
- **常见缺失 / 反模式**：技能栏批发 Python/R/Spark/TensorFlow/Kafka/Hadoop/Docker/LangChain,一问“Spark 用在哪个项目”就答“就了解一点”【反模式·技术名词批发商:列表很长、能用上的没几个】;只会执行别人写好的 SQL,无独立多表关联/取数记录。

### 5. 业务理解与指标体系（满分 12）
- **好的样子**：能把业务问题抽象成建模问题,实习项目写清“解决了什么业务问题”而非只堆技术栈;有 DAU/GMV/留存率等核心指标异动归因分析经历;能把建模结论和业务结果连起来——说得清“模型 AUC 提升了、业务结果有没有跟着变”,做过“离线涨、在线不涨”这类问题的排查分析尤其受认可。
- **应届证据**：实习经历有业务问题→建模动作→业务结果的因果链表述;参与过核心指标异动分析或指标体系搭建;能说清模型提升与业务收益的关系;经历强调“负责了端到端流程”(取数→建模→上线→监控)而非只做某一环。
- **常见缺失 / 反模式**：实习写“参与 XXX 项目数据分析”,追问贡献时只剩 SQL 提数、Excel 画图,说不出用了什么模型、指标效果如何【反模式·实习打杂党:挂名项目里查无此人的真实产出】;项目名称高大上(“智能 XX 系统”)但只讲技术不讲业务价值,问“这个模型让业务变好了多少”一片空白。

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度必须给出 why:① 指出简历中具体命中/缺失的事实——模型选型理由与评估指标(AUC/KS/GAUC 而非准确率)、特征构造与数据清洗细节、AB 实验/因果推断(CUPED/Uplift/AUUC/DID)证据、SQL+Python+上线 pipeline 实操记录、业务问题→建模→业务结果的因果链,分别写进 evidenceFound/gap;② 说明在校招数据科学(业务落地型,ML 应用/建模/特征工程)语境下为何重要,例如建模+统计基本功是一票否决级、AB 实验与因果推断是区分初级与高级候选人的大厂杀手锏、离线指标涨而在线不涨的归因能力极受认可;③ 命中反模式时直接点名——「调包侠」「准确率幻觉」「Kaggle搬运工」「结论党」「离线成功主义」「技术名词批发商」「实习打杂党」,不得空泛(“数据能力一般”无效)。分数必须与 why 一致,不得先打分再倒补理由。

## 改写指引（禁编造铁律）
改写只能基于简历已有内容重组/量化/补证据链,目标是把候选人“已有”的项目/实习句讲精准:写清用了什么模型(并补上为何选它)、解决什么业务问题、数据量级多大、用什么指标(AUC/KS/GAUC/AUUC)衡量、效果提升多少,用精准动词与可量化指标增强可信度。缺具体数字时只在该处用 [具体数字] 占位并在 reason 说明“建议补充真实指标(如 AUC、样本量、提升幅度)”。严禁替候选人添加原句没有体现的能力或技术名词——简历没写过 CUPED/因果推断/上线 pipeline,就绝不在改写里凭空加上,凡简历缺失的能力一律走“建议补充(gap_advice)”而非编造;尤其不得把“协助/参与某项目”夸大为“独立/主导建模”。original 必须是简历原文一字不差。

## 本土惯例与硬规则
中国校招数据科学(业务落地型)本土惯例核查:① 学历硬门槛——头部互联网(字节/阿里/美团)数据科学岗事实上要求硕士及以上,双非硕士无相关实习基本简历关即出局,211/985 本科 HC 极少且竞争激烈;② 笔试不可跳——拼多多等公司笔试缺席后流程直接终止、无补救;③ 简历漏洞即出局——写“精通”某技术被当场追问答不上,直接淘汰且印象极差,技能栏建议分层写(主力/熟悉/了解)不堆砌;④ 证书优先级——有效:天池/Kaggle 奖牌(前 10%-20%,须注明排名百分比)、顶会论文(KDD/NeurIPS/ICML,共同作者亦可)、金融数科岗的 CFA/FRM;无效甚至负分:无项目支撑的在线证书(Coursera ML 结业证单列)、低级别数学建模奖项充当主要亮点;⑤ 格式——一页纸(硕士多段实习+论文可到两页,须信息密度高),每条经历用“场景-动作-结果(含量化数字)”结构、动词开头,不要自我评价栏;⑥ 反信号——硕士只有课程项目无实习、项目名称高大上但细节一问三不知、全程通用版简历不按岗位定制;⑦ 与岗位区分:这是 ML 应用/建模/特征工程的业务落地数据科学岗,不是纯算法研究岗(深度学习/顶会权重对此岗有限,树模型与业务落地更重要),也不是只做 SQL 取数+BI 报表的数据分析师岗。
