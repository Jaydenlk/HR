# 策略产品经理（策略产品经理 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`strategy-product-manager-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 数据硬功底(SQL取数×AB实验×指标体系)（满分 28）
- **好的样子**：策略产品的非弹性硬通货:SQL 能独立取数(写得出多表 join、group by、窗口函数)、有真实跑过 AB 实验的经历(说得清假设、分流方式、核心指标与护栏指标、显著性判断/P值/MDE/最小样本量、实验结论与上线决策),并能搭一套指标体系(北极星指标 + OSM/AARRR 拆解,区分结果指标与过程指标)。Python(pandas)做数据清洗/分析是加分。每项能力都绑定一个『用它解决了什么策略问题、带来了多少量级变化』的具体场景(如『AB 实验验证新召回策略,实验组点击率 +X%,显著性 p<0.05,推全上线』)。
- **应届证据**：在实习/项目/竞赛描述里写出『用 SQL 从 X 万级日志中取数并定位转化漏斗第 X 环节流失』『设计 AB 实验对比两套策略,样本量 X,核心指标 CTR 提升 X% 且通过显著性检验』,工具与产出绑定出现;数据分析比赛(如 DataWhale/Kaggle/校企赛)或课程项目里有完整的『提出假设→取数→分析→给结论』闭环。
- **常见缺失 / 反模式**：技能栏写『熟悉 SQL/会做数据分析』,正文却找不到一句自己取过数、跑过实验;或把 Excel 透视表当数据能力,从未接触 AB 实验与显著性概念,一问『怎么判断实验有没有效果』就答不上『P 值/置信区间』。【反模式·SQL熟悉了选手:技能栏一行『熟练 SQL/Python』,全文零取数零建表零实验,面试官第一题让手写一个分组取 Top3 的 SQL 就当场卡壳,策略岗这是直接出局题】

### 2. 策略建模能力(模糊问题→可执行策略×场景闭环)（满分 27）
- **好的样子**：能把一个模糊业务问题拆成可落地的策略模型,这是策略 PM 区别于通用 PM 的命门。围绕主流策略场景体现:搜索(意图识别/query 改写/精准结果展现)、推荐(召回→粗排→精排→重排、正负反馈体系、冷启动)、增长(用户分层/流失预警/补贴策略)、风控/反作弊、商业化广告(出价/竞价机制)。能讲清一条策略的完整闭环:发现问题→定位归因→设计策略(规则/模型/分层)→设计实验验证→评估迭代,而不是只描述需求或界面。能用业务语言说清『为什么这么分层/这条规则解决了什么』。
- **应届证据**：实习/项目里有具体策略产出:如『针对新用户冷启动设计了基于 X 的分层推荐策略』『搭建流失预警规则将高风险用户召回率提升 X%』,并写明自己负责拆解问题的哪一环(归因/规则设计/实验/评估);毕设、课程设计、竞赛涉及搜索/推荐/增长场景的策略设计,能说清模型逻辑而非只有界面原型。
- **常见缺失 / 反模式**：把执行类、画原型、写需求文档的通用 PM 经历套上『策略』二字,通篇是『负责 XX 功能的需求设计与跟进上线』却没有任何分层、规则、实验、归因;或只罗列『熟悉推荐系统/搜索引擎』名词,讲不出自己设计过哪条具体策略、解决了什么问题。【反模式·策略二字贴牌党:做的是排期跟进、原型评审的纯执行活,简历里硬塞『策略』二字包装,录用官追问『你这条策略的假设是什么、怎么验证有效』就原形毕露】【反模式·名词复读机:满屏召回排序冷启动出价竞价术语,却答不出自己亲手设计过哪条策略、调过哪个参数,只是把面经八股抄进了简历】

### 3. 策略相关实习(团队属性×任务实质)（满分 18）
- **好的样子**：有真实的策略/数据产品/数据分析岗实习,团队属性清晰:大厂搜索/推荐/广告/风控/增长策略团队(字节、美团、阿里、快手、拼多多、腾讯等的策略产品或数据产品岗)最佳,垂类大厂或独角兽的策略/数据岗次之。任务写得出实质:参与了哪条策略的迭代、做了哪些数据分析支撑决策、跑了哪些实验、产出了什么结论并影响了什么指标,能说清自己独立做了什么(取了什么数、提了什么假设、设计了什么策略)。
- **应届证据**：实习经历栏写明公司全称 + 策略/数据相关团队 + 起止时间,每段用 2-3 条 bullet 描述具体策略/数据任务与可量化产出(如『支撑 X 业务线的策略迭代,通过数据分析定位 X 问题,推动策略调整带来 X 指标提升 X%』),而非一句『参与产品相关工作』。
- **常见缺失 / 反模式**：用纯执行的通用产品实习、运营实习、市场实习冒充策略经验,以为『在互联网公司做过 PM』就够;或在策略团队打杂(只做了会议记录、竞品调研搬运)却美化成『参与策略设计』,面试追问任务实质即穿帮。【反模式·沾个互联网就算仔:拿通用 PM、运营、市场实习往策略岗上靠,觉得在大厂待过、行业沾边就能补上策略实习的空缺,录用官第一刀就砍没有数据与实验痕迹的『伪策略』经历】

### 4. 学历背景与量化基本功(院校×专业×数理)（满分 15）
- **好的样子**：本/硕院校有竞争力(头部大厂策略岗隐形看 985/211 或海外名校),专业偏数理/计算机/统计/经济金融等量化方向更佳(策略岗需要数理基础支撑统计推断与算法理解)。文科专业需用数据项目、SQL/Python 实操、统计课程来补足量化短板。附 GPA(策略岗看重逻辑与学习能力)。有概率统计、机器学习、计量经济、因果推断等课程基础是实打实的加分。
- **应届证据**：教育背景栏写明院校 + 专业 + 全日制 + 预计毕业时间,附 GPA 及排名;若专业偏文,在技能/课程栏列出自学的概率统计、机器学习、SQL/Python 课程或证书,并在项目里用数据分析实操佐证量化能力。
- **常见缺失 / 反模式**：院校专业普通又无任何数据项目/统计基础补足,对策略岗的数理门槛是隐形劣势;或专业是纯文科却既无量化课程也无数据实操,只靠『对数据敏感』这类自我评价撑场面。【反模式·我对数据很敏感型选手:专业与数理无关、简历零数据项目零统计课程,却在自我评价里写一句『数据敏感度高、逻辑思维强』就当作量化能力,录用官看的是你跑过的实验和取过的数,不是形容词】

### 5. 数据敏感度与业务理解(归因×数感×场景认知)（满分 12）
- **好的样子**：能用数据驱动的思维体现对业务的理解:看到指标波动会主动拆解归因(是流量变了还是转化变了、哪个环节、什么人群),对量级有基本数感(知道一个 App 的 DAU/转化率大致量级、能做费米估算),理解所投场景的核心指标(电商看 GMV/转化漏斗、内容看时长/留存、广告看 ROI/eCPM)。哪怕是『课程项目里对某 App 的留存做了分层归因』『费米估算过某场景的市场规模』也胜过完全无数感。能区分相关与因果,知道 AB 实验是验证因果的手段。
- **应届证据**：在项目/实习/竞赛描述中出现指标拆解归因、漏斗分析、用户分层、费米估算、北极星指标等动作,并说清自己怎么拆的、得出什么洞察;对目标公司所在赛道的核心指标与商业模式有具体认知,而非纯名词罗列。
- **常见缺失 / 反模式**：简历从头到尾只有功能描述和工具罗列,完全不出现任何指标拆解、归因、量级、漏斗,显示只会做事不会用数据想问题;或一谈『提升用户体验』就停在感性描述,给不出任何衡量指标。【反模式·体验提升玄学派:满篇『优化体验、提升满意度、让产品更好用』,却说不出用哪个指标衡量、提升了多少、怎么归因,策略岗一切靠数据说话,无指标的『提升』等于没做】

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度的 why 必须落到简历事实,按以下结构展开,分数与 why 严格一致:

① 命中/缺失事实(写进 evidenceFound / gap):
- data_sql_experiment:evidenceFound 写出具体的取数/实验事实(如『用 SQL 从日志取数定位漏斗流失』『设计 AB 实验,核心指标 CTR +X%,p<0.05』);gap 写『技能栏列 SQL/Python 但正文零取数零实验』或『从未出现 AB 实验/显著性概念』。
- strategy_modeling:evidenceFound 写出具体策略产出与场景(如『为新用户冷启动设计分层推荐策略』);gap 写『通篇为需求设计/原型跟进等纯执行,无任何分层/规则/实验/归因』或『只罗列推荐搜索术语,无亲手设计的策略』。
- strategy_internship:evidenceFound 写出团队属性与具体任务(如『某大厂推荐策略团队,支撑 X 策略迭代』);gap 写『仅有通用 PM/运营/市场实习,无策略岗经历』或『策略团队实习描述只有打杂无任务实质』。
- education_quant:evidenceFound 写院校 + 专业方向 + GPA + 量化课程;gap 写『文科专业且无量化课程无数据实操补足』。
- business_data_sense:evidenceFound 写命中的数据动作(如『对某 App 留存做分层归因』『费米估算市场规模』);gap 写『全文无指标拆解/归因/漏斗/量级,只有功能描述』。

② 校招语境下为何重要:必须说明该维度在策略产品校招的实际筛选作用——数据硬功底(SQL/AB 实验)是大厂策略岗的非弹性硬门槛,SQL 写不出、实验讲不清直接过滤;策略建模是策略 PM 区别于通用 PM 的命门,没有策略闭环的简历会被判定为『伪策略』;策略相关实习是录用官实际筛选的实质项,且不可被纯执行的通用 PM 实习替代;院校与量化基本功是隐形筛选线;数据敏感度与业务理解是简历铺垫、面试 case 与费米估算环节的核心。

③ 命中反模式直接点名:若命中则直呼『SQL熟悉了选手』『策略二字贴牌党』『名词复读机』『沾个互联网就算仔』『我对数据很敏感型选手』『体验提升玄学派』等,不得空泛说『有待提升』。

分数对齐:data_sql_experiment 全文无任何取数/实验佐证封顶不及格(大厂策略岗硬门槛);strategy_modeling 通篇纯执行无策略闭环判为『伪策略』不得给中等以上分;strategy_internship 仅有通用 PM/运营实习不得给中等以上分;business_data_sense 零数据动作给低分但不一票否决(属铺垫维度)。

严禁在 why 中出现『满分的 X%』『给分不超过』『故给满分』『扣 X 分』等内部比例话术,why 只陈述简历事实、反模式命名与校招筛选逻辑。

## 改写指引（禁编造铁律）
严格遵循『禁编造』干净句式,绝不替候选人添加原句没有体现的能力、技术名词、团队层级或数据:

1. 把简历『已有』的策略/数据经历句讲精准:明确写出用了什么数据手段(SQL 取数/AB 实验/分层/归因/费米估算)、解决什么策略问题(召回优化/冷启动/流失召回/转化提升)、量级多大(取了 X 万条数据、实验样本 X、核心指标提升 X%)。
   - 例:原句『参与产品功能优化』→ 改『针对 [原文已提及的场景] 的 [原文已提及的问题],用 [原文已提及的方法] 设计策略并通过 AB 实验验证,核心指标 [原文指标] 提升 [具体数字]』(场景、问题、方法、指标均须取自原文,缺则留占位或走 gap_advice)。

2. 用精准动词替换模糊词,但不得越级:原文写『参与/协助』就保留『参与』,严禁夸大为『独立主导/负责』;原文确写了独立设计策略才可用『设计/主导』。把通用 PM 的『负责需求/跟进上线』如实保留,绝不擅自改写成『设计策略』来伪造策略经历。

3. 只在缺数字处用 [具体数字] 占位:如『核心指标提升 [具体数字]%』『实验样本量 [具体数字]』『从 [具体数字] 万条日志中取数』,让候选人自行填真实数字,绝不代填。

4. 严禁编造能力:简历没写过 SQL/Python/AB 实验/某策略场景,一律不得在改写中添加;没体现过的实验显著性、指标提升、团队层级、策略闭环不得凭空生成;不得把界面/原型类工作粘贴包装成策略建模。

5. 凡简历缺失的关键能力(如无 SQL 取数、无 AB 实验、无策略产出、无量化背景、无数据敏感度),一律走 gap_advice 给『建议补充』而非在 rewrite 里编造:
   - gap_advice 示例:『建议补充一次真实的 SQL 取数或 AB 实验经历并写明假设、指标与显著性结论』『建议把某段经历的策略闭环补全:发现问题→归因→设计策略→实验验证→评估』『建议补充一段搜索/推荐/增长/风控等策略相关团队的实习』『建议补充指标拆解归因或费米估算的具体动作以体现数据敏感度』。

## 本土惯例与硬规则
出局级硬规则:
- 无任何数据硬功底佐证(SQL 取不了数、从未接触 AB 实验与显著性):大厂搜索/推荐/广告/风控策略岗直接过滤,这是策略产品岗最硬的出局线,无商量余地。
- 通篇纯执行无策略闭环(只有需求设计/原型/排期跟进,零分层/规则/实验/归因):被判定为『伪策略』,与通用 PM 无差异,失去策略岗竞争力。
- 简历虚假信息:大厂背调 + 实习证明核验,夸大策略经历、伪造实验数据一旦发现直接出局。
- 无策略/数据相关实习:在大厂策略岗层级竞争力极弱,纯执行通用 PM 实习不可替代策略实习。

证书/技能优先级(策略产品岗明确共识):
1. SQL 实操能力 — 非弹性硬通货,必须能独立写多表 join / group by / 窗口函数,面试常手写。
2. AB 实验 + 统计推断(显著性/P值/MDE/置信区间/样本量) — 策略岗核心方法论,必考。
3. Python(pandas)数据分析 — 数据清洗与分析加分,数据产品岗权重更高。
4. 推荐/搜索/广告等场景的算法理解(召回/排序/冷启动/出价机制) — 理解即可,无需会建模,能讲清策略逻辑即加分。
5. 明确反信号:堆砌纯文科软技能(沟通/协调/PPT)而无任何数据与策略实操,对策略岗不加分反暴露方向不匹配。

格式偏好:
- 大厂走网申/内推系统,简历本科 1 页、研究生最多 2 页。
- 数据能力(SQL/AB 实验)、策略产出(具体策略 + 指标变化)、策略相关实习三项必须在简历首屏可见(策略岗最看重的三件套)。
- 每条经历用『动作 + 数据手段 + 量化结果』结构,核心指标提升务必带百分比或量级。

加分项(策略产品特有):
- 数据分析/算法类竞赛获奖(Kaggle、DataWhale、校企数据赛、数学建模国奖)。
- 大厂搜索/推荐/广告/风控/增长策略团队实习经历(团队属性越核心越好)。
- 有完整策略闭环的项目(发现问题→归因→设计策略→AB 实验验证→评估迭代)。
- 因果推断、机器学习、计量经济等课程或项目背景(数据产品/增长策略岗专项加分)。
- 个人数据分析作品集/博客(展示真实取数与分析能力)。

反信号(策略产品特有):
- 把纯执行的通用 PM、运营、市场经历套『策略』二字包装(伪策略)。
- 满屏召回/排序/冷启动/出价术语却讲不出亲手设计的任何一条策略(名词复读机)。
- 描述经历只用『负责/参与/优化体验』而无任何数据手段与量化结果。
- 自我评价里写『数据敏感度高/逻辑强』却全文零数据动作佐证。
