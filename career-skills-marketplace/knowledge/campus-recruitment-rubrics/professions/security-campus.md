# 网络安全（网络安全 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`security-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 实战漏洞挖掘战绩（满分 30）
- **好的样子**：简历顶部直接列出可验证的真实战绩：大厂SRC（阿里/腾讯/字节/补天/漏洞盒子）有效高危漏洞并附平台ID或致谢截图，或真实CVE/CNVD编号（面试官会当场查），或CISCN/强网杯/网鼎杯省级以上CTF名次。漏洞描述量化到位「提交13个高危，其中10个未授权访问」，并能讲清从信息收集到PoC验证的完整链路。
- **应届证据**：漏洞平台个人主页ID/月榜排名、CNVD/CVE编号、SRC致谢名单截图、CTF战队名与比赛名次、带PoC和截图的漏洞复现记录或技术博客。这些是面试官扫简历时最先看的硬通货。
- **常见缺失 / 反模式**：只写「熟悉SQL注入/XSS等常见漏洞原理」却没有一个真实环境提交记录；CTF只填校内赛/低知名度赛名次，反而暴露视野窄；漏洞描述用「挖过一些漏洞」不量化。【反模式·靶场仔：只在DVWA/Vulhub里点过几下，简历却写「精通漏洞挖掘」,真实SRC/CVE一个都没有】

### 2. 攻防演练实战经历（满分 22）
- **好的样子**：护网（HW/HVV）/攻防演练经历写清自己的真实角色与战果而非堆次数：红队拿下了主机/域控（量化到XX个据点、得分XX），自己写过绕过安全产品（WAF/EDR）的工具或脚本；蓝队有具体的流量研判、告警规则编写、误报治理案例。内网渗透能讲横向移动、域控打法、HTTP不出网时的隧道通信方案。
- **应届证据**：护网项目中的具体职责描述+量化战果、自研绕过工具的GitHub仓库或截图、蓝队告警规则/研判报告样例、内网渗透复现笔记（横向移动/隧道搭建）。
- **常见缺失 / 反模式**：护网经历写了三次却答不出「拿没拿下主机」「用什么手法绕过」；以培训生身份「参与」护网当成主力经历写；只写「参加护网红队」不写任何战果和手法。【反模式·护网充数党：护网×3挂满简历,一问拿没拿下据点就支支吾吾,批量写护网在2026届已是反信号】

### 3. 技术深度与原理理解（满分 20）
- **好的样子**：不停在「是什么」层面，能讲清楚机理：Web侧说得清二次注入、宽字节注入、WAF绕过的具体手法；中间件/框架漏洞（Shiro、Fastjson、Log4j）的反序列化利用链讲得出来；给一个陌生CVE能说出分析思路。简历用漏洞复现记录、代码审计经历、自己分析CVE全过程的原创博客来佐证深度。
- **应届证据**：原创技术博客（自己分析一个CVE的完整过程，非转载）、代码审计项目记录、反序列化/中间件漏洞的复现笔记带PoC、研究生方向的攻防论文或导师带队项目。
- **常见缺失 / 反模式**：自评「精通渗透测试」，面试追问二次注入修复方案或Fastjson利用链就答不上；技术博客全是「转载自CSDN」；只会用工具不懂底层原理。【反模式·夸大精通症：简历写「精通渗透」,一问WAF具体怎么绕、反序列化链怎么构造就卡壳,夸大比留白还减分】

### 4. 编程与安全工具开发（满分 16）
- **好的样子**：Python/Go/Java至少精通一门并能展示真东西：GitHub上有自己写的安全工具（漏扫、信息收集、绕过脚本），star≥100显著加分；渗透/漏洞研究方向改写过sqlmap/nuclei、写过PoC/exp，证明不只是工具使用者。安全开发岗体现工程能力与安全知识的交叉。
- **应届证据**：GitHub个人仓库链接（代码是自己写的、有commit历史、有star而非空仓或全是fork）、自研PoC/exp、对开源工具的二次开发记录、安全平台/扫描器的工程项目。
- **常见缺失 / 反模式**：技能栏罗列Burp/Nmap/Metasploit/sqlmap一长串却没有一行自己的代码；GitHub链接点进去是空仓或全是fork（用人部门会主动检索，空仓比没有更扣分）；自称「热爱安全」却无任何公开技术积累。【反模式·工具搬运工：技能栏把全家桶工具名抄了一遍,GitHub却是空仓,面试官一眼识破当场卡壳】

### 5. 垂直方向专精与合规意识（满分 12）
- **好的样子**：选定1-2个方向打深（Web/应用安全、二进制逆向Pwn、安全开发平台、安服应急、AI安全），而非Web+逆向+云+移动全写「熟悉」。顶尖实验室方向（玄武/科恩/无恒）配CVE或开源项目；AI安全（2026新热点）有大模型攻防/Agent越狱的复现或论文。项目描述体现合规意识：写「在授权范围内完成渗透测试并提交修复报告」而非「获取他人敏感信息」。
- **应届证据**：聚焦单一方向的成果集群（如Web向的SRC+CTF+代码审计三合一）、知名战队经历（Nu1L/AAA/r3kapig/Vidar等）、安全方向论文/专利、授权渗透报告样例、OSCP/CISP-PTE证书。
- **常见缺失 / 反模式**：Web+逆向+二进制+云+移动全写「熟悉」却无任何一项有深度；项目描述写「获取他人敏感信息」暴露零合规意识（安服岗第一问就是授权边界）；简历暗示过非授权测试。【反模式·全栈安全幻觉：每个方向都写「熟悉」却没一个能深挖,招聘官明确排斥「全而不精」,而暗示越权测试更是国央企一票否决】

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
逐维度给出 why，必须落到简历可见事实，禁止空泛套话：

1. 实战漏洞挖掘战绩（权重30，入围决定项）：① evidenceFound 写命中的硬通货——是否出现真实 SRC 平台 ID/月榜、CVE/CNVD 编号、省级以上 CTF 名次、量化的高危漏洞数（如「13 高危含 10 未授权」）；gap 写缺失——只有「熟悉漏洞原理」无任何提交记录，或 CTF 只填校内/低知名度赛。② 在网络安全校招语境下，这是招聘官扫简历的第一眼硬通货，一个真实 CNVD 价值远超十条「熟悉原理」，直接决定能否入围技术面。③ 若全是靶场无真实环境，直接点名「靶场仔」；若 CTF 唯分主义堆小赛名次，点名其「到职场业务逻辑漏洞会卡死」。分数必须与战绩硬度一致：有真实 CVE/SRC 致谢→高分；只有原理罗列→低分。

2. 攻防演练实战经历（权重22，基础门槛）：① evidenceFound 写护网经历是否含真实角色与量化战果（拿下主机/域控、据点数、得分、自研绕过工具）；gap 写只堆「参加护网×N」无任何战果手法、或以培训生身份参与。② 2026 届绝大多数候选人都写了护网，已是基础门槛而非加分项，差异化全在「带队/拿据点/自研工具」。③ 命中只堆次数答不出手法的，直接点名「护网充数党」并说明批量写护网已成反信号。分数与战果质量一致：拿下域控+自研绕过工具→高分；只写参与无战果→中低分。

3. 技术深度与原理理解（权重20，通过率/终面决定项）：① evidenceFound 写是否有原创 CVE 分析博客、代码审计、反序列化/中间件漏洞复现带 PoC；gap 写自评「精通」但无任何深度佐证、博客全为转载。② 安全岗面试深度追问是常态（二次注入修复、Fastjson 利用链、给陌生 CVE 谈思路），这一维度决定能否通过技术面。③ 命中夸大的直接点名「夸大精通症」，并指出夸大比留白还减分。分数与可佐证的深度一致：有原创 CVE 分析→高分；只有自评精通无佐证→低分。

4. 编程与安全工具开发（权重16，乙方/安全开发岗必考）：① evidenceFound 写是否有自研安全工具 GitHub 仓库（自己写的、有 commit、有 star）、自研 PoC/exp、对 sqlmap/nuclei 的二次开发；gap 写技能栏堆工具名无代码、GitHub 空仓或全 fork。② 安全开发岗与漏洞研究岗必考编程，用人部门会主动检索 GitHub，空仓比没有更扣分。③ 命中堆工具名无代码的直接点名「工具搬运工」。分数与代码真实产出一致：有 star≥100 的自研工具→高分；只罗列工具清单→低分。

5. 垂直方向专精与合规意识（权重12，中高端分水岭+一票否决项）：① evidenceFound 写是否聚焦 1-2 个方向的成果集群、知名战队经历、授权渗透报告措辞；gap 写五大方向全写「熟悉」无深度、项目描述用「获取他人敏感信息」暴露零合规、或暗示越权测试。② 招聘官明确排斥「全而不精」，且合规意识是安服岗第一问，越权暗示在国央企是一票否决。③ 命中全写熟悉的点名「全栈安全幻觉」，暗示越权的明确标注一票否决风险。分数与专精度+合规意识一致：单方向打深+授权措辞规范→高分；全面铺开无深度或合规缺失→低分，合规红线触发直接压分。

## 改写指引（禁编造铁律）
严格遵循「禁编造」干净句式，把简历已有内容讲精准，绝不替候选人添加原句没有的能力。

核心原则：
- 只对简历「已有」的漏洞/护网/项目/实习句做精准化改写——讲清用了什么技术、解决什么问题、规模量级多大，用精准技术动词（如「构造PoC验证」「编写绕过脚本」「复现利用链」）和可量化指标增强可信度。
- 严禁把简历没写的能力/技术名词塞进改写句。凡简历没有体现的能力（如没写 CVE 就不能编 CVE 编号、没写编程就不能说会写工具），一律走「建议补充（gap_advice）」提示候选人自查，而非代为编造。
- 严禁夸大：原句是「参与/协助护网」绝不改成「独立完成/主导红队」；原句是「使用 sqlmap」绝不改成「改写 sqlmap」。角色与贡献度必须忠于原文。
- 只在缺数字处用 [具体数字] / [据点数] / [高危占比] 占位，提示候选人自己回填真实数据，不替其编造数值。

改写示例（合法）：
- 原句「挖过一些漏洞」→「向[SRC平台名]提交[具体数字]个有效漏洞，其中高危[具体数字]个（如未授权访问、越权）」（仅当简历确有提交事实时）。
- 原句「参加护网红队」→「以红队成员参与[项目名]攻防演练，负责[简历已写的具体职责]」——若简历未写战果，则在 gap_advice 提示「建议补充本次护网的具体战果，如是否拿下主机/据点数/绕过手法」。
- 原句「会用 Burp、sqlmap」→保留为工具使用表述，不升级为「自研工具」；在 gap_advice 提示「若有自研脚本或 PoC，建议附 GitHub 链接」。

gap_advice（针对缺失能力，只建议不编造）：
- 无真实战绩→「建议补充任意一项真实实战：SRC 提交记录（附平台 ID）、CNVD/CVE 编号、或省级以上 CTF 名次」。
- 无 GitHub→「建议整理一个自研安全工具或 PoC 仓库并放链接，注意避免空仓或全 fork」。
- 合规措辞缺失→「项目描述建议改为「在授权范围内完成渗透测试并提交修复报告」，体现合规边界意识」。
- 方向过散→「建议聚焦 1-2 个方向（如 Web 安全或安全开发）突出成果集群，避免五大方向全写「熟悉」」。

## 本土惯例与硬规则
中国网络安全校招本土惯例核查点（按重要性分条）：

【出局级硬规则】
1. 零实战出局：没有 SRC/护网/安全实习任意一项真实经历，会被专业安全公司直接筛掉。
2. 大厂学历关：字节/腾讯/阿里/美团 HR 严卡学历，非 985/211（部分要求硕士）即便技术极强也可能过不了 HR 筛（有真实案例：长亭红队+快手+美团+阿里四段实习仍因学历被淘汰）。对策是大二大三即出校实习争取转正，绕过 HR 直接进技术面。
3. 造假即死：安全行业面试官技术水平极高，会现场细问漏洞/护网每个细节，项目造假被识破当场出局。
4. 合规红线（一票否决，含国央企）：有违法入侵记录，或简历暗示过非授权测试（如「获取他人敏感信息」）。

【证书优先级（应届视角）】
- 有实质作用：OSCP（国际认可，渗透方向加分显著）> CISP-PTE（国内渗透，含金量适中）> NISP 二级（入门，聊胜于无）。
- 甲方/国企加分：CISP、等保相关资质（多需工作年限，应届一般拿不到）。
- 无实质作用却常被高估：NISP 一级（太基础）、各类网校培训结业证书。
- 总排序：真实 CVE/CNVD > 任何证书 > OSCP > CISP-PTE > NISP 二级。

【格式偏好】
- 1 页（最多 2 页），PDF 格式，命名「岗位-姓名-学历-简历.pdf」。
- 技能条禁用「熟练/精通/了解」模糊词，直接写量化事实，如「Web 渗透测试（SRC 高危 X 个）」。
- 顶部黄金区域放最硬的料：CVE/CNVD 编号、SRC 平台 ID、GitHub 链接、CTF 战队名+名次——这是面试官最先扫视的。
- 项目用 STAR 结构并量化：漏洞数量、高危占比、影响资产规模。

【反信号（出现即扣分）】
- 「参加 XX 网络安全培训班」→被标记为买课入行、技术不扎实。
- 只有靶场（DVWA/Vulhub）无真实环境经历。
- 技术文章全是「转载自 CSDN」。
- 护网是「以培训生身份参与」（机构带薪参与模式）。
- GitHub 空仓或全是 fork（用人部门会主动检索）。

【加分项（本岗特有）】
- 大厂 SRC 月榜排名、补天/漏洞盒子致谢。
- 知名战队经历（Nu1L/AAA/r3kapig/Vidar，面试官会认）。
- 原创深度技术博客（自己完整分析一个 CVE，非转载）。
- 研究生期间导师带攻防项目或安全方向论文/专利。
- AI 安全（2026 新热点）：大模型攻防、Agent 越狱研究有复现或论文。
