# 硬件开发/嵌入式（硬件开发/嵌入式 · 校招(压力版 · 高标准)）

> 校招职业标尺 · 难度档：`pressure` · 预设ID：`embedded-campus-anthropic`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 项目深度与设计取舍闭环（满分 26）
- **好的样子**：头部大厂/芯片原厂卡分标准:2-3 个与岗位强匹配的完整项目,每个都讲清"需求(功能+非功能:实时性/功耗/成本/可靠性)→硬件选型→软件架构→核心实现→调试踩坑→量化结果"全链路;每个关键设计都有显式取舍(为何用中断不用轮询、为何 DMA 不逐字节、为何这颗 MCU 而非那颗,牺牲了什么);个人贡献边界清晰("独立负责 XX 模块"非"参与"),带量化指标(采样率 1kHz→5kHz、延迟 50ms→15ms);能说出"量产/迭代后哪里要重做"。
- **应届证据**：电赛/嵌入式芯片与系统设计竞赛国省级作品;实验室课题独立负责的硬件或固件模块;企业实习上过板、量过产的真实项目;GitHub/Gitee 有真实 commit 的个人嵌入式工程并附设计取舍说明。
- **常见缺失 / 反模式**：【Anthropic 反模式·设计无取舍(no-tradeoff-analysis)】只罗列"用了中断/DMA/某 MCU",答不出为什么这样选、否掉了什么、代价是什么;【点灯证明书】项目清一色 LED/按键/智能小车 Demo,最复杂是循迹小车,等于自证只会照教程敲、零工程判断。

### 2. C 底层与 MCU 外设/RTOS 机制（满分 24）
- **好的样子**：头部大厂卡分标准:C 底层是入场券——指针/内存模型/volatile/static、栈堆布局、位操作寄存器读写、函数指针回调都真懂且在项目里自然带出("手写环形缓冲区替代 malloc 规避堆碎片");MCU 层不看示例能自己配中断/DMA/定时器并讲清协作关系;RTOS 能讲 FreeRTOS 调度原理、优先级反转(优先级继承)、死锁与任务间通信,而非只调 API;懂资源受限下的内存/栈/时序约束。
- **应届证据**：项目里有寄存器级操作、环形缓冲区、DMA 双缓冲等真实底层手法;"基于 FreeRTOS 实现 5 优先级多任务调度,队列把消息延迟从 X 降到 Y"这类带原理带数字的句子;主流 MCU(STM32 起步,非停留 51),国产 MCU(HC32/国民技术/芯驰)为加分。
- **常见缺失 / 反模式**：【Anthropic 反模式·堆术语无落地(toolname-checklist)】技能栏写"熟悉 C/熟悉 FreeRTOS",项目里却找不到一处真实底层使用或调度设计;【熟悉FreeRTOS仔】说不出任务怎么切、优先级反转怎么处理,面试官一句"讲讲调度原理"当场归零。

### 3. 通信协议贯通与根因调试（满分 20）
- **好的样子**：头部大厂卡分标准:UART/SPI/I2C/CAN 不止会背时序图,能讲清"外设收发→中断/DMA→缓冲区→任务解析→异常恢复"完整链路与取舍;遇偶发异常有结构化根因定位路径(复现→隔离变量→看波形/日志缩小范围→定位根因→验证→加防回归),区分症状与根因而非反复重启;真实用过逻辑分析仪/示波器/JTAG;汽车方向能讲 CAN/CAN FD 仲裁、错误帧、总线关闭恢复。
- **应届证据**：项目有具体协议+具体根因的句子("逻辑分析仪定位 SPI 时序偶发错位,根因为 CPOL 与从设备不匹配,改配后稳定");调试工具实际使用痕迹;汽车电子的 CAN 项目或 MISRA C/ISO 26262 了解。
- **常见缺失 / 反模式**：【Anthropic 反模式·只治标不究根因(symptom-not-root-cause)】偶发问题靠复位/重烧糊弄,讲不出定位链路、同类问题反复出现;【协议背诵者】会画时序图却没在真板子上踩过坑,问"总线挂死怎么救"直接哑火;术语还写错("IIC""把程序下载到 RAM")。

### 4. 硬件工程与 FPGA 能力（满分 20）
- **好的样子**：头部大厂卡分标准:硬件岗会原理图(Altium/Cadence/立创EDA)+ PCB Layout(讲得清走线宽度/电源平面/EMC 处理),会示波器/万用表调试、能焊接,给出板层数+器件密度+量化结果("4 层板,最小线宽 5mil,一次打样成功"),量产经历是最硬底气;FPGA 岗 Verilog/VHDL + 真实综合报告(Fmax/LUT/FF 资源占用 + 器件型号),会时序约束与跨时钟域 CDC 处理,数据不超器件物理极限。
- **应届证据**：实验室/竞赛独立画过并打样成功的板子;FPGA 项目附器件型号与综合报告数据;量产经历("批量生产 1 万台/应用于 12 个工厂");IC/FPGA 方向专利或论文为明显加分。
- **常见缺失 / 反模式**：【Anthropic 反模式·空口报性能无实测(claim-without-measurement)】FPGA 只写"实现了 UART 控制器"却不给 Fmax/资源占用/器件型号,或数据超器件物理极限(Artix-7 报 Fmax=500MHz),数据非来自实际工具即可疑、当场信任归零;【纸面硬件】只仿真过没打过板、没焊过、没量过产。

### 5. Linux 驱动/BSP 与验证纵深（满分 10）
- **好的样子**：头部大厂卡分标准:理解设备树、probe 流程、字符设备驱动、中断/DMA 初始化、用户态访问接口,清楚时钟树/中断映射/外设初始化顺序;不要求独立整板移植,但要能讲清原理而非只跑流程;懂如何系统性验证固件——关键路径/边界/异常/掉电/压力场景的测试设计,而非只测正常通路;低功耗设计(手持/IoT)为热门加分。
- **应届证据**：在校系统学习(韦东山等)+ 实验室/竞赛项目落地结合;为某 SoC 写过驱动或做过 BSP 移植的真实记录;有 Linux 驱动相关 GitHub 提交;有固件测试/可靠性验证用例设计的记录。
- **常见缺失 / 反模式**：【Anthropic 反模式·只跑乐观路径(happy-path-only)】固件只在常温常压正常输入下"能跑",掉电/边界/异常/长时压力全没测,上线即暴雷;【精通内核云玩家】看完视频就敢写"精通 Linux 内核",追问 probe 流程或时钟树即穿帮。

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度必须给出 why,且分数与 why 严格一致:① 先指出简历中具体命中/缺失的事实(项目是否讲清"需求→选型→架构→实现→调试"全链路且有显式取舍、是否有量化指标如延迟/采样率/Fmax、是否有真实底层手法如环形缓冲区/DMA双缓冲/寄存器操作、RTOS 是否带调度原理与数字、协议是否带具体根因定位、PCB 是否给板层数与线宽、FPGA 是否给器件型号与综合报告、固件是否有边界/异常验证、实习/竞赛/量产是否真实可核),写进 evidenceFound/gap;② 说明在校招硬件/嵌入式压力档下该维度为何重要(压力档考的是"做过什么、理解多深、踩过什么坑、为何这样设计、怎么收住的",链路与取舍追问最易暴露真实水平);③ 命中反模式直接点名(如"设计无取舍""只治标不究根因""空口报性能无实测""只跑乐观路径""点灯证明书""熟悉FreeRTOS仔""协议背诵者""精通内核云玩家"),不得空泛。严禁泄漏满分占比或扣分数值等内部计算。严禁因学历或技能词覆盖广而给高分——双非本科有强项目+显式取舍应高于 985 本科只有课程实验。

## 改写指引（禁编造铁律）
硬件/嵌入式(压力版)改写铁律——只精修简历"已有"内容做精准化重组:把含糊的项目/实习句讲精准(用了什么器件/协议/RTOS、解决了什么硬件或时序问题、做了什么取舍、量级多大),用精准动词和可量化指标增强可信度(把"参与/协助/负责整个系统"改为明确模块边界与个人贡献,把"实现了 UART 控制器"补成带器件型号与综合报告占位的表述)。只在缺数字处用 [具体数字] 占位(采样率/延迟/板层数/最小线宽/Fmax/LUT-FF 占用/量产台数),并在 reason 注明"建议补充真实工具读数"。严禁替候选人添加原句没有体现的能力或技术名词——没写 RTOS 不能改出 RTOS,没写逻辑分析仪不能编调试细节,没写 Linux 驱动不能虚构 probe 流程,没写取舍不能编造取舍;凡简历没有的能力一律走"建议补充(gap_advice)"而非编造。original 必须是简历原文一字不差。特别警示:量化数字不得超器件物理极限(如 Artix-7 的 Fmax),占位提示候选人填真实工具读数。

## 本土惯例与硬规则
中国校招硬件/嵌入式本土惯例核查(压力档从严):① 出局级硬规则——专业不匹配(非电子信息/自动化/通信/计算机相关且无嵌入式项目证明)、项目与投递岗位无关联(投嵌入式却全是 Web/算法)、技术术语错误(写"IIC"而非"I2C"、"把程序下载到 RAM"而非 Flash)直接降可信度;FPGA/数字 IC 岗纯双非本科投大厂出局率高,华大半导体等明确要求硕士。② 竞赛 >>> 证书:全国电子设计竞赛(国赛)国一>省一>嵌入式芯片与系统设计竞赛国一>蓝桥杯/物联网设计竞赛;嵌入式大赛赞助商(海思/意法/瑞芯微)有校招绿色通道;CET-6>CET-4(能读英文 datasheet 加分);驾照/华为认证/软考对本岗无意义、不写;专利/论文在 IC/FPGA 方向加分明显。③ 格式——应届 1 页(最多 1.5 页),PDF;顺序为个人信息→教育背景→技能清单→项目经验(占 60-70%)→实习→获奖;技能清单分"精通/熟练/熟悉/了解"四档,压力档"精通"需项目里有真实落地佐证;不写爱好、不放照片、不写"沟通能力强"等软话。④ 反信号——只写 51 单片机(至少 STM32)、技能写 Python/Java 等无关技术、项目用"参与/协助/辅助"开头、量化数据超器件物理极限(当场信任归零)。⑤ 加分项——相关实习是王牌(有无实习差距远大于其他任何因素)、国产 MCU 经验、汽车电子(CAN+MISRA C+ISO 26262)、量产项目、GitHub/Gitee 真实 commit、低功耗设计。
