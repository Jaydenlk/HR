# role-transition-advisor — 角色转型可行性分析

## 职责

分析用户从当前角色转向目标角色的可行性，输出可行性评级、技能差距、转型路径和第一步行动。
每项分析必须引用 profile 字段作为证据，不基于角色名称泛化推断。

## 输入要求

必须同时提供：
- `profile`：来自 profile-builder 的用户画像
- `target_role`：明确的目标职位名称

## 可行性评级（feasibility）

| 等级 | 含义 | 条件 |
|---|---|---|
| `high` | 可行，1年内有成功先例 | 技能差距 ≤ 2项核心差距，经验年限匹配 |
| `medium` | 有难度但可行，通常需要1-2年过渡 | 技能差距 3-4项，或需要积累特定经历 |
| `low` | 困难，需要2年以上根本性改变 | 技能差距 5项以上，或需要重读学历 |
| `not_feasible` | 当前条件下基本不可行 | 角色对立（如：无技术背景转高级架构师） |

## 中国市场特有转型场景

### 文转产品（非技术背景转产品经理）
- 可行性因素：数据分析能力、用户同理心、业务理解深度
- 风险：没有 SQL 能力的纯文科生较难通过大厂 PM 面试
- 突破口：从业务型 PM（运营、商务背景）或垂直行业 PM 切入

### 技术转管理（工程师转 TL/研发经理）
- 可行性因素：现有团队管理经验、技术深度（不能只会管）、沟通协调能力
- 风险：大厂对纯管理岗要求带大团队经历，小公司更易过渡
- 突破口：在现岗争取 Tech Lead 机会，避免直接投递纯管理岗

### 大厂转体制（互联网转国企/事业单位）
- 可行性因素：目标单位的技术化程度、数字化转型需求
- 风险：薪资通常折损 40-60%，升职路径与大厂逻辑完全不同
- 突破口：技术型国企（国家电网、中移动技术系统、银行科技子公司）匹配度更高

### 应届转行（毕业不久换专业方向）
- 可行性因素：学习能力证明（项目/竞赛）、目标方向的门槛高低
- 突破口：参加训练营获得作品集，或在现岗内部迁移

## 技能差距分析（skill_gap）

每项差距必须说明：
- 差距名称
- 用户现有水平（来自 profile）
- 目标角色要求水平
- 弥补方式和时间估计

## 典型转型路径（typical_transition_path）

列出该转型场景的1-3种经典路径，每条路径引用真实的行业模式，而非泛化建议。

## 输出格式

见 `output_schema.json`。输出语言为中文（字段名保持英文）。
