# campus-recruitment-diagnosis · 校招简历诊断技能

给**应届生 / 校招生**用的简历诊断、打分与改写助手。它按你**目标职业**的专属标尺逐维评分、列出差距、预演面试官会怎么追问,并给出**绝不替你编造**的改写建议。

> 不是校招(社招 / 转行 / 中高级岗)请改用 `match-diagnosis` 等社招技能。

---

## 这个 skill 做什么

1. **诊断打分**:按你目标职业的锁定标尺(各职业维度/满分不同,权重和=100)逐维打分,给出 `total_score`、每维得分与理由、对照标尺的缺口。
2. **本土惯例核查**:核中国校招的硬规则(如技术栈分「精通/熟悉/了解」三档、项目要有 GitHub 或大厂实习、竞赛含金量排序),逐条标 通过 / 提醒 / 不通过。
3. **面试追问预演**:针对你简历里得分低或可能被质疑的点,预演面试官的追问 + 给**诚实**的准备方向(引导你补齐真实能力,不教你圆谎)。
4. **防编造改写**(需你确认后才做):只优化你简历**已有**的句子;简历没有的数字一律用 `[具体数字]` 占位;没有的能力 / 实习 / 方法只会写成「建议你具备后再写入」,**绝不**替你坐实虚构内容。

覆盖 11 大类、60+ 校招职业(技术研发 / 产品运营 / 设计 / 数据 / 市场销售 / 金融 / 财务 / 人力资源 / 职能法务 / 咨询战略 / 行业垂类)。

## 必要输入

| 输入 | 是否必填 | 说明 |
|------|---------|------|
| `resume_text` | **必填** | 简历正文。请把**经历 / 项目 / 技能 / 竞赛荣誉**都贴上;竞赛名次、证书、语言成绩(如「六级552分」「ACM 区域赛银牌」)请连同**原文具体分数 / 名次**一并提供——这些会被忠实读取计入评分,漏写会拉低你的分。 |
| `target_profession` | **必填** | 目标职业。可写中文名(如「后端开发」「投行(IBD)」「HRBP」)或标尺 ID(如 `backend-campus`)。找不到精确职业时,会取最相近的并显式告诉你「按最接近的 X 评估」。没填的话,会先从你简历推断 1-2 个候选让你二选一。 |
| `difficulty_tier` | 选填 | 难度档。`standard`=校招友好档(默认);`pressure`=压力档(大厂卡人 / 想被狠批),**仅当你明确要求**才用。 |
| `jd_text` | 选填 | 目标岗位 JD 正文。仅作背景参考,**不改变**职业标尺的评分维度与满分。 |

**缺简历**:不诊断,会请你先贴简历。
**缺职业**:先从简历推断候选让你确认,再开评。

---

## 输出长什么样

严格按 `output_schema.json` 输出,核心字段:

- `summary` / `confidence`(high · medium · low · insufficient)/ `evidence_used` / `risks` / `cannot_determine` / `follow_up_questions` / `next_actions`
- `diagnosis`:
  - `total_score`:总分(各维之和;信息不足无法评分时不给精确分)
  - `dimensions[]`:每维 `name` / `score` / `max` / `why`(落到你简历的具体事实)/ `evidenceFound`(抄你简历原句)/ `gap`(对照标尺的缺口)
  - `conventionChecks[]`:本土惯例核查(`pass` / `warn` / `fail`)
  - `interviewHooks[]`:面试追问预演(命中点 + 追问 + 准备方向)
- `rewrite_suggestions[]`:改写建议(你确认后才出)
- `honesty_boundary`:诚实边界声明——本次做了 / 没做什么、哪些建议需你真实具备后再写入

## 使用示例(后端开发)

输入:

```yaml
target_profession: 后端开发
difficulty_tier: standard
resume_text: |
  张同学 / 计算机科学与技术 / 应届2026
  实习:字节跳动 后端开发实习
    - 优化慢查询:EXPLAIN 定位全表扫描后加复合索引,接口耗时从 800ms 降到 30ms
    - 用 Redis 分布式锁解决并发下单超卖,支撑日均 10 万订单处理
  竞赛:ACM-ICPC 亚洲区域赛 银牌;LeetCode 已刷 420 题
  技能:精通 Java(JVM/GC/并发),熟悉 MySQL/Redis,了解 Go
```

会得到:五维评分(编程语言 / 计算机基础 / 系统设计 / 工程实践 / 算法,满分 20/25/25/20/10)+ 惯例核查 + 面试追问预演;确认后再给只优化原句、不编造的改写建议。

更多场景见 `examples/`:

| 示例 | 演示什么 |
|------|---------|
| `examples/happy-path.md` | 强简历对口职业 → 高分 + 高置信度,且不漏读竞赛/成绩 |
| `examples/low-evidence.md` | 弱背景信息不足 → 据实低分 + 降置信度 + 追问,不臆造 |
| `examples/source-conflict.md` | 简历自评与项目证据矛盾 → 摆出冲突、采信实证、追问澄清 |
| `examples/bad-input.md` | 简历过短 / 职业不存在 → 拒绝硬评分、索要信息 |
| `examples/fabrication-guard.md` | 你要求「加上提升40%」而简历无此数据 → 占位 / 降级,绝不坐实 |

## 我们对「不编造」的承诺(核心红线)

- **数字铁律**:改写后句子里的每个具体数字,都要能在你简历原文里逐字找到;找不到的一律写 `[具体数字]` 占位。
- **缺口铁律**:简历没有的能力 / 实习 / 方法,只会写成「建议补充」并提示**面试穿帮风险**,绝不在「优化句」里替你坐实。
- **确定性兜底**:交付前用 `scripts/check_fabrication.mjs` 机械复核(原句子串校验 + 数字校验),拦住任何漏网的编造。
- **忠实读取**:你写明的竞赛名次 / 成绩 / Star 数会照抄计入证据,不臆断「未标注 = 不高」。

标尺基于截至模型知识更新日的中国校招通行做法;具体公司当季要求可能不同,以官方 JD 为准。
