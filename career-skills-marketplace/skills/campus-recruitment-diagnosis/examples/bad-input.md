# 示例 04 · bad-input —— 简历过短 / 目标职业不存在

## 场景说明

两类坏输入合并演示:① 简历正文过短(无经历/项目/技能,无法解析评分);② 目标职业在标尺索引里既无精确项也无最相近项(伪职业)。
预期:**不硬评分**——`confidence: insufficient`、不产出精确 `total_score`、说明缺什么、给恢复路径。

---

## 输入

### 子场景 A:简历过短
```yaml
target_profession: 后端开发
resume_text: "我想找后端工作,求诊断。"   # 无经历/项目/技能/竞赛,无可评分内容
```

### 子场景 B:目标职业不存在
```yaml
target_profession: 星际舰队指挥官          # index.md 中既无精确项也无最相近项
resume_text: |
  陈同学 / 计算机 / 应届
  项目:用 Spring Boot 做了订单系统的增删改查
```

---

## 期望 output 要点

### 子场景 A(简历过短)
- `confidence`: **insufficient**
- **不输出** `diagnosis.total_score`(信息不足无法评分,按 output_schema 省略该字段)
- `cannot_determine`:列出「无任何可评分的经历/项目/技能/竞赛」
- `follow_up_questions` / `next_actions`(**非空**):请用户贴上完整简历正文(经历/项目/技能/竞赛荣誉)后重新诊断
- `summary`:一句话说明无法诊断及原因(简历正文不足)
- **禁止**凭空生成五维分数或编造简历内容

### 子场景 B(职业不存在)
- `confidence`: **insufficient**(或在能找到最相近职业时降为 `medium` 并显式告知;本例为纯虚构职业,无最相近项 → `insufficient`)
- `cannot_determine`:「目标职业『星际舰队指挥官』在校招标尺库中无精确项也无最相近项,无法锁定评分标尺」
- `follow_up_questions`:请用户确认一个真实存在的目标职业(可列 1-2 个由简历推断的候选,如「后端开发」)
- **不**强行套用某个标尺打分

---

## rationale(为什么这样判)

坏输入案例的考点是 **拒绝硬评分**:校招诊断的两个必要输入(可解析简历 + 可命中职业)缺任一,都不应产出貌似精确的分数。
- 简历过短 → 没有评分原料,`insufficient` + 索要简历,而非给一个看起来合理的 60 分;
- 职业纯虚构 → 没有可锁定的标尺,`insufficient` + 让用户确认真实职业;**注意**与「找不到精确但有最相近」区分:后者降 `medium` 并显式告知按最接近的 X 评估,本例无最相近故 `insufficient`。
这区别于 low-evidence:那里简历可解析、职业可命中,只是证据弱 → 给低分 + 追问;这里是连评分前提都不具备 → 拒评 + 索要。
