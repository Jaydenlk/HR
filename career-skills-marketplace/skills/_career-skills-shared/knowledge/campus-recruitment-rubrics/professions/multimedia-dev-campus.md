# 音视频/多媒体开发（音视频/多媒体开发 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`multimedia-dev-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 编解码与流媒体协议基本功(编码原理×协议栈)（满分 28）
- **好的样子**：懂的是「为什么」而非「是什么」:能讲清 H.264/H.265 的帧内/帧间预测、I/P/B 帧与 GOP 结构、IDR、码率控制(CBR/VBR/CRF)的取舍,知道 H.265 比 H.264 省 30%-50% 码率但编码复杂度/功耗更高所以要靠硬编。封装(MP4/FLV/MPEG-TS)与裸流(YUV/PCM/NALU)分得清。流媒体协议按场景对得上号:直播推流 RTMP、点播切片 HLS/DASH、实时互动 WebRTC/RTP/RTCP、监控 RTSP,并能说清各自的延迟量级(RTMP 秒级、HLS 数秒、WebRTC 数百毫秒)。音频侧懂 AAC/Opus、采样率/声道/PCM。AV1/SVC/HEVC 的演进趋势有概念。所有概念最好挂在自己做过的项目上讲,而不是孤立背诵。
- **应届证据**：在项目/课程描述里把编解码与协议知识「用出来」:如「基于 H.264 NALU 解析实现关键帧抽取」「用 RTMP 推流 + HLS 分发搭建直播链路,实测端到端延迟 X 秒」「调整 GOP 长度与 CRF 值平衡画质与码率」。技能栏列编解码标准(H.264/H.265)、协议(RTMP/WebRTC/HLS/RTSP)、封装格式时,正文要有对应的使用场景佐证,而非干列名词。
- **常见缺失 / 反模式**：只会背「I 帧是关键帧、P 帧参考前面、B 帧参考前后」这类八股定义,一问「为什么直播 GOP 要短、点播可以长」或「丢一个 P 帧会怎样」就答不上来,暴露纯背诵无理解。或协议张冠李戴(说实时互动用 RTMP、把 HLS 当低延迟方案)。【反模式·八股复读机:把帧类型、协议名词背得滚瓜烂熟却串不成一条完整链路,面试官追问一层原理立刻穿帮,这是音视频校招第一刀】

### 2. 音视频项目深度(端到端链路×可量化产出)（满分 30）
- **好的样子**：有真正动手做过的音视频项目,而非只跑通别人的 demo。典型硬通货项目:基于 FFmpeg + SDL/OpenGL 实现音视频同步播放器(讲得清音视频同步、PTS/DTS、解码-渲染流水线)、转码/剪辑管线、直播推拉流链路(RTMP 推 + HLS/WebRTC 拉)、RTC 实时通话、播放器二次开发(ijkplayer/ExoPlayer 架构改造)。最关键是说得清「自己在链路哪一环、解决了什么具体问题、效果用什么指标衡量」——首屏秒开时间、卡顿率、端到端延迟、CPU/内存占用、VMAF/PSNR 画质分等。项目能落到某个真实赛道场景(直播、短视频、点播、监控、RTC)更佳。
- **应届证据**：项目经历栏每段写明:用了什么技术栈(FFmpeg 二次开发/WebRTC/OpenGL ES)、解决了什么音视频问题(同步/低延迟/画质/兼容性)、可量化的产出(把卡顿率从 X% 降到 Y%、首屏从 X ms 优化到 Y ms、VMAF 提升到 X 分)。代码挂 GitHub 并写明自己负责的模块。区分清楚是个人项目、课程项目还是实习产出。
- **常见缺失 / 反模式**：项目只是「用 FFmpeg 命令行把 A 格式转成 B 格式」「跟着教程跑通了一个播放器 demo」,没有任何自己写的解码/渲染/同步逻辑,本质是调命令行工具不是做开发。或项目描述只有「实现了一个音视频播放器」一句话,既无技术细节也无任何指标。【反模式·命令行搬运工:把敲几条 ffmpeg -i 转码命令、跑通现成开源 demo 当成音视频开发经历,简历里没有一行自己写的编解码/渲染代码,录用官一眼看穿这是「用工具」不是「做工具」】【反模式·跟练复刻侠:全是照着 B 站教程一比一复刻的播放器/直播 demo,改个 UI 就当项目,问到「为什么这么设计」「换个场景怎么改」全卡壳,因为从没真正理解过链路】

### 3. 工程能力与跨端集成(C/C++底子×硬解硬件×多端)（满分 18）
- **好的样子**：C/C++ 是这个岗位的硬门槛(音视频核心库基本是 C/C++ 写的),有真实 C/C++ 项目佐证,懂内存管理、多线程、性能 profiling。跨端集成能力是区分度所在:移动端懂硬解码硬编码(Android MediaCodec、iOS VideoToolbox)及其与软解(FFmpeg)的取舍、JNI/NDK 集成、OpenGL ES/Metal 渲染;了解不同平台的兼容性坑(机型适配、色彩空间、旋转)。网络编程基础扎实(Socket、TCP/UDP/IP、HTTP)。会用 Wireshark/抓包、ADB、性能分析工具定位问题。能把音视频 SDK 嵌入到一个完整的客户端/服务端应用里跑起来。
- **应届证据**：在项目里体现:「用 NDK 把 FFmpeg 交叉编译进 Android,通过 JNI 调用解码」「用 MediaCodec 做硬解码 + OpenGL ES 渲染,对比软解降低 CPU 占用 X%」「用 Wireshark 抓包定位 RTMP 推流丢包问题」。技能栏的 C++/Android/iOS/OpenGL 都要能在项目正文找到对应实战,而非孤立罗列。
- **常见缺失 / 反模式**：技能栏写「精通 C++/熟练 OpenGL ES/掌握 WebRTC」,全简历找不到一个用到它们的项目,一问具体怎么集成、踩过什么坑就露馅。或只会在 PC 上跑 demo,完全没碰过移动端硬解/JNI/渲染这些真实工程环节,而音视频岗大头恰恰在客户端跨端。【反模式·精通牌吹牛皮:技能栏一水儿「精通/熟练」,WebRTC、OpenGL ES、MediaCodec 全写上去了却连一行集成代码都拿不出,正文零佐证,面试问集成细节当场失忆】

### 4. 性能·功耗·画质优化(QoE 指标×端到端调优)（满分 14）
- **好的样子**：理解音视频是「体验驱动」的工程,核心是一组可量化的 QoE/QoS 指标:首屏秒开、卡顿率、端到端延迟、清晰度/画质(VMAF/PSNR/SSIM)、CPU/GPU/内存/功耗、流畅度。懂得在画质-码率-延迟-功耗之间做权衡(典型:H.265 省码率但费电,要靠硬编平衡;弱网下降码率保流畅 vs 保画质)。RTC 场景懂弱网对抗(丢包重传 NACK、前向纠错 FEC、自适应码率 ABR、抖动缓冲 Jitter Buffer)。做过哪怕一次真实的优化并量化了收益(把卡顿率降 X%、功耗降 Y%、VMAF 提升 Z 分),就远胜空谈。知道 VMAF 95+ 基本无可见损失、70 分明显糊这类工程直觉。
- **应届证据**：在项目/实习里写出具体优化动作 + 量化收益:「通过自适应码率 + Jitter Buffer 调优,把弱网卡顿率从 X% 降到 Y%」「切换硬解码使播放功耗下降 X%」「用 VMAF 评测对比不同 CRF 档位,在画质 95 分前提下压低 X% 码率」。出现 QoE/卡顿率/秒开/VMAF/弱网 等关键词并说清自己做了什么。
- **常见缺失 / 反模式**：整份简历不出现任何性能/画质/体验指标,项目只说「实现了播放功能」却从不提卡顿、延迟、功耗、画质,显示只会让功能「跑起来」不懂让它「跑得好」——而音视频岗的价值恰恰在后者。或张口「优化了性能」却拿不出任何前后对比数字。【反模式·能播就行党:项目止步于「画面能出来、声音能响」,从没量过卡顿率/首屏/功耗/画质,简历里一个 QoE 指标都没有,在以体验为生命线的直播短视频赛道直接掉档】

### 5. 学历背景与算法基本功(专业匹配×刷题底子)（满分 10）
- **好的样子**：本/硕为计算机、电子信息、通信、软件工程等相关专业,数字信号处理、计算机网络、操作系统、数据结构等核心课与音视频高度相关,可列出相关课程成绩。算法刷题是大厂校招笔试/面试的通用门槛(音视频岗同样要过算法关),有 LeetCode/竞赛记录或在面经里能扛住中等难度题。信号处理/图像处理/计算机图形学背景对音视频是天然加分。GPA 不低、有 ACM/蓝桥等竞赛奖项加分。学历背景是隐形筛选线,但在这个岗位上它的权重低于真实音视频项目——项目能力可以补学历,纯高 GPA 补不了零项目。
- **应届证据**：教育背景栏写明院校 + 专业 + 全日制 + 预计毕业时间,附 GPA,列出数字信号处理、计算机网络、操作系统、计算机图形学等与音视频相关的核心课。算法能力用竞赛奖项、ACM/蓝桥获奖或 LeetCode 刷题量体现。
- **常见缺失 / 反模式**：把全部精力堆在刷题和 GPA 上,音视频项目一片空白,以为「计算机科班 + 算法强」就能拿音视频岗 offer,实则这是个强项目导向的细分方向,无项目则在简历筛选环节就掉队。或专业完全不相关又无任何音视频项目/课程补足匹配度。【反模式·刷题绩点党:简历上 LeetCode 刷了几百题、GPA 拉满,音视频项目栏却空空如也,以为算法强就能横扫,殊不知音视频岗第一看的是编解码/项目而非纯算法】

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度的 why 必须落到简历事实,按以下结构展开,分数与 why 严格一致:

① 命中/缺失事实(写进 evidenceFound / gap):
- codec_protocol_fundamentals:evidenceFound 写出命中的编解码/协议认知及其使用场景(如「基于 H.264 NALU 解析做关键帧抽取」「RTMP 推 + HLS 拉搭直播链路」);gap 写「仅有 I/P/B 帧定义式背诵,无任何原理或链路应用」或「协议张冠李戴,说实时互动用 RTMP」。
- av_project_depth:evidenceFound 写出项目技术栈 + 解决的音视频问题 + 量化产出(如「FFmpeg+OpenGL 播放器,处理音视频同步,卡顿率降 X%」);gap 写「项目仅为 ffmpeg 命令行转码,无自写编解码/渲染代码」或「只有『实现了播放器』一句,无技术细节无指标」。
- engineering_crossplatform:evidenceFound 写出 C/C++ 项目及跨端集成实战(如「NDK 交叉编译 FFmpeg,JNI 调用解码」「MediaCodec 硬解 + OpenGL ES 渲染」);gap 写「技能栏列 C++/WebRTC/OpenGL ES 但正文零集成佐证」或「只在 PC 跑 demo,无任何移动端硬解/JNI/渲染经历」。
- performance_qoe_optimization:evidenceFound 写出具体优化动作 + 量化收益(如「ABR+Jitter Buffer 把弱网卡顿率从 X% 降到 Y%」);gap 写「全文无卡顿率/秒开/延迟/功耗/VMAF 等任何 QoE 指标」。
- education_algorithm:evidenceFound 写院校 + 专业方向 + 相关核心课 + 算法/竞赛记录;gap 写「专业不相关且无音视频项目/课程补足」或「仅高 GPA+刷题,音视频项目空白」。

② 校招语境下为何重要:必须说明该维度在音视频校招的实际筛选作用——编解码与协议基本功是面试八股+追问的第一关(背诵层一问原理即穿帮);音视频项目深度是简历筛选与面试的核心,不可被「跑通 demo / 命令行转码」替代,是本岗最强区分项;C/C++ 与跨端集成是工程门槛(核心库皆 C/C++、岗位大头在客户端);性能/QoE 优化是直播短视频赛道的价值所在(体验指标是生命线);学历算法是通用门槛但权重低于真实项目(项目补得了学历,GPA 补不了零项目)。

③ 命中反模式直接点名:若命中则直呼「八股复读机」「命令行搬运工」「跟练复刻侠」「精通牌吹牛皮」「能播就行党」「刷题绩点党」,不得空泛说「有待提升」。

分数对齐:codec_protocol_fundamentals 仅有八股定义无原理理解只能算缺失、不得给中等以上;av_project_depth 仅命令行转码/跑通 demo 不得给中等以上分(本岗最看重的区分项,零真实项目封顶不及格);engineering_crossplatform 工具无佐证只能算缺失;performance_qoe_optimization 零 QoE 指标给低分但不一票否决(属体验进阶维度);education_algorithm 是隐形筛选线,纯高 GPA 零项目不得给高分。

严禁在 why 中出现「满分的 X%」「给分不超过」「故给满分」「扣 X 分」等内部比例/扣分话术,只陈述简历事实、命中反模式与缺口。

## 改写指引（禁编造铁律）
严格遵循「禁编造」干净句式,绝不替候选人添加原句没有体现的能力、技术名词、项目环节或指标:

1. 把简历「已有」的音视频项目/实习句讲精准:明确写出用了什么技术栈(原文已提及的 FFmpeg/WebRTC/OpenGL ES/MediaCodec)、解决了什么音视频问题(同步/低延迟/画质/兼容性/弱网)、自己负责链路哪一环、量级与产出多大(首屏秒开、卡顿率、延迟、CPU/功耗、VMAF)。
   - 例:原句「实现了一个音视频播放器」→ 改「基于 [原文提及的技术栈] 实现音视频播放器,负责 [原文已写的模块,如解码/渲染/同步],处理 [原文已提及的问题,如 PTS/DTS 同步]」(技术栈、模块、问题均须取自原文,缺则留占位或走 gap_advice)。

2. 用精准动词替换模糊词,但不得越级:原文写「参与/基于教程实现」就保留对应表述,严禁夸大为「独立设计/主导架构」;原文确写了自研逻辑才可用「自研/独立实现」。绝不把「跑通 demo」改写成「自主开发」。

3. 只在缺数字处用 [具体数字] 占位:如「将卡顿率从 [具体数字]% 降到 [具体数字]%」「首屏秒开优化到 [具体数字] ms」「VMAF 提升到 [具体数字] 分」,让候选人自行填真实数字,绝不代填。

4. 严禁编造能力与指标:简历没写过 H.265/WebRTC/OpenGL ES/硬解码/某协议,一律不得在改写中添加;没体现过的 QoE 指标(卡顿率/秒开/VMAF/功耗)、链路环节、跨端集成不得凭空生成;尤其不得把命令行转码包装成「编解码开发」、把跑通 demo 包装成「自研播放器」。

5. 凡简历缺失的关键能力(如无自写编解码/渲染代码、无跨端集成、无任何 QoE 指标、无协议链路实践),一律走 gap_advice 给「建议补充」而非在 rewrite 里编造:
   - gap_advice 示例:「建议补充一个有自研编解码/渲染/同步逻辑的音视频项目,而非仅命令行转码」「建议在项目中补充端到端 QoE 指标(如卡顿率、首屏秒开、延迟、VMAF)及优化前后对比」「建议补充移动端硬解码/JNI/OpenGL ES 渲染等跨端集成的实战经历」「建议补充对编解码原理或流媒体协议链路的实际应用,而非仅背诵定义」。

## 本土惯例与硬规则
出局级硬规则:
- 应聘音视频/多媒体开发岗却零音视频项目(只有 Web/纯后端等无关项目):简历筛选环节直接过滤,这是强项目导向的细分方向,无相关项目几乎无竞争力。
- 不会 C/C++ 或无任何 C/C++ 项目佐证:音视频核心库基本是 C/C++,纯 Java/前端背景且无 C/C++ 实战在硬核岗位直接掉档(偏 Android/iOS 上层 SDK 岗可放宽,但底层引擎/编解码岗无商量)。
- 简历虚假信息(把命令行转码/跑通 demo 包装成自研、虚标未掌握的协议与编解码能力):面试追问原理与集成细节当场穿帮,大厂背调亦会核验。
- 非全日制学历 / 无法按时拿到毕业证+学位证双证:部分国企/央企硬性出局。

技能与项目优先级(本岗明确共识):
1. 真实音视频项目(有自研编解码/渲染/同步/推拉流逻辑 + 可量化 QoE 产出)— 最强区分项,优先级高于一切。
2. 编解码与协议基本功(懂原理而非背定义)+ C/C++ 工程能力 — 面试硬门槛。
3. 跨端集成与硬解码(MediaCodec/VideoToolbox/NDK/OpenGL ES)— 客户端方向核心竞争力。
4. 性能/功耗/画质优化与 QoE 指标 — 直播短视频赛道的价值高地。
5. 算法刷题 — 通用门槛,过线即可,不是本岗的差异化项。

格式偏好:
- 大厂走网申/内推系统,简历本科 1 页、研究生最多 2 页。
- 音视频项目应在简历首屏可见,每段项目用 2-3 条 bullet 写清「技术栈 + 解决的音视频问题 + 量化产出」。
- 代码项目附 GitHub 链接并写明个人负责模块,开源贡献(给 FFmpeg/WebRTC/ijkplayer 等提 PR)是顶级背书。

加分项(音视频特有):
