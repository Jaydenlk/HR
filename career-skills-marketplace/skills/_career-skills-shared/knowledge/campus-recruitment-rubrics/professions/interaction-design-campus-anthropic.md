# 交互设计（交互设计 · 校招(压力版 · 高标准)）

> 校招职业标尺 · 难度档：`pressure` · 预设ID：`interaction-design-campus-anthropic`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 作品集——设计决策深度与可追问性（满分 30）
- **好的样子**：对标阿里/腾讯/字节交互岗:作品集前两个项目就要让面试官判定上限,每个核心项目走完整链路"背景与目标用户→用研痛点洞察→方案推导(重点)→交互稿+交互说明→数据/验证",且每个交互决策都经得起逐层追问(为什么这样解、和竞品差异、改成另一种会牺牲什么);最关键的是写清"抓住了哪个关键痛点、推导链如何成立",让人从 1-2 个项目就看出思考深度,而非看一堆精美页面。
- **应届证据**：PDF 作品集(10MB 内、纯中文、30-40 页舒适区)为主体 + 可访问链接补充;简历正文用"项目名+核心问题+我的设计决策+结果"点出可深聊的 1-2 个代表作;能就任一界面回答"如果这里改成 X 会失去什么"。
- **常见缺失 / 反模式**：【Anthropic 反模式·结论先行(solutioning before framing)】只堆精美页面与 Mockup,看不到每张图背后的决策、和竞品的差异、洞察是什么,一问"为什么这么设计"就答不上(美图仔);【Anthropic 反模式·"还行就过"的模糊自评】对自己交互方案只会说"这样比较顺/比较清晰",给不出 design-critique 式的具体诊断(注意力竞争、读序、操作可见性)。

### 2. 交互状态与流程完整性(交互的本体)（满分 24）
- **好的样子**：面试官真正用来区分水准的核心项。好的应届项目"用户流程图＋任务流程(含异常场景)＋原型加交互说明"三件套齐全;交互说明系统覆盖状态矩阵——弹窗触发时机/位置/目的、loading/空态/error/禁用/边界态、异常引导、操作反馈,而不只是把线框画精细;能体现信息架构能力、建过控件库或沿用设计规范是明显加分。
- **应届证据**：作品集完整呈现流程图、信息架构图、带标注的交互说明文档,以及对异常态/空状态/边界态的处理截图;简历可一句话点出"梳理 X 个核心流程、补全 N 个异常场景、沉淀控件库"。
- **常见缺失 / 反模式**：【Anthropic 反模式·只做正常路径(Happy Path only)】原型画得很细、视觉还原度高,但交互说明缺位,弹窗触发逻辑、边界状态、异常引导一概没有,本质还停在画图阶段(画框仔);把"交互设计"误解为"把线框画得更精细",对触发时机、边界态、异常流这些交互本体只字不提——而这恰是面试官区分及格线与优秀的标尺。

### 3. 用研到设计的闭环严谨度（满分 16）
- **好的样子**：重点不在用研报告多厚,而在能否精炼呈现并从研究结论清晰推导出设计决策,形成"研究→洞察→方案"可追溯闭环;清楚区分"用户说的"与"用户做的",不把一句访谈当全部依据;Persona/体验地图/故事板用在刀刃上,每个研究结论都能对应到具体功能或设计响应;参与过真实访谈/可用性测试的写清场景与结论。
- **应届证据**：作品集用研章节"关键洞察提炼+对应设计响应"逐条对照;实习中参与用户访谈/可用性测试的具体场景与结论;简历可写"通过 N 次访谈定位核心痛点 X,据此设计了 Y 功能"。
- **常见缺失 / 反模式**：【Anthropic 反模式·调研搬运(research as decoration)】把课程用研报告原封不动塞进作品集,方法堆满却没提炼洞察、更没推导出设计(调研报告搬运工);【Anthropic 反模式·听其言不观其行(say vs do)】只引用用户原话当依据,从不看真实行为;Persona+旅程图+亲和图齐全,后面设计稿却找不到任何对应。

### 4. 产品 Owner 视角与业务判断（满分 14）
- **好的样子**：大厂明确考察"以产品 Owner 视角而非工具人视角看需求",这是区分一般与优秀的分水岭。好的应届在实习描述里讲得清 5W:需求从哪来、解决什么问题、为什么做这个需求、上线后什么结果、后续如何迭代;有主动做竞品分析并发现优化点的经历更佳;能用 JTBD 的口吻说明"用户在某场景下想达成什么"。
- **应届证据**：实习经历对需求来源与业务目标的描述(需求背景+解决的问题+上线结果+迭代思路),以及参与竞品分析、主动提优化点的具体记录;简历用"接到 X 需求→理解业务目标→输出方案→上线后指标变化"的句式。
- **常见缺失 / 反模式**：【Anthropic 反模式·工具人视角(execution-only mindset)】实习只写"负责某模块交互设计",讲不清需求为什么做、解决什么业务问题、上线后怎样,全程是接稿画图的执行末端(画稿工具人)——大厂面试官最想剔除的就是这种只会画交互稿、不懂为什么做的候选人。

### 5. 可访问性、跨职能协作与 AI 素养（满分 16）
- **好的样子**：能在团队项目中讲清与 PM/研发/QA 的协作节点、是否跟进高保真还原与设计评审、是否盯过上线数据,让人看出"少了你这块会缺什么";具备 WCAG 2.1 AA 基线意识(对比度 ≥4.5:1、触控 ≥44×44、可见焦点与合理 Tab 顺序、表单 label 与可理解报错);工具上 Figma 精通为标配、Axure 熟练,能用 Principle/Framer 做可交互 Demo、有前端基础或在设计流程中用过 AIGC 工具(2025-2026 明确加分,百度 MEUX JD 直接写明)。
- **应届证据**：实习/团队项目对个人职责与协作节点的清晰界定、可交互 Demo 链接;作品集中有对比度/触控尺寸/焦点态标注或 a11y 走查记录;用 AI 辅助设计的实际案例;工具力靠 Demo 与作品验证而非进度条。
- **常见缺失 / 反模式**：【Anthropic 反模式·能力靠进度条自证(skill bar self-rating)】用"Figma 90%、Axure 85%"雷达图冒充能力,团队项目说不清个人贡献,AI 写一行"熟悉 AIGC"却无任何应用(进度条仔);【Anthropic 反模式·可访问性事后补(accessibility as afterthought)】通篇不提对比度/触控尺寸/键盘可达,把 a11y 当上线后再说的边角料。

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
逐维度给分必须落到简历事实,禁止空泛,且分数与 why 严格一致:① 命中/缺失写进 evidenceFound / gap——前两个项目是否还原决策链且写出关键痛点、能否就单个交互决策讲出权衡、是否有流程图+异常场景+交互说明三件套与完整状态矩阵、用研洞察是否逐条对应设计、实习是否体现 Owner 视角与上线结果、是否提及对比度/触控/焦点等 a11y 基线、是否有可交互 Demo 与协作职责界定;② 说明在交互设计校招(对标大厂)语境下为何重要(作品集是一票否决级硬门槛、状态完整性是面试实际区分水准的核心、用研要闭环不是报告厚度、Owner 视角是分水岭、a11y 是大厂合规基线、AIGC 是 2025-2026 明确加分);③ 命中反模式直接点名(结论先行 / "还行就过"模糊自评 / 只做正常路径 / 调研搬运 / 听其言不观其行 / 工具人视角 / 能力靠进度条自证 / 可访问性事后补),不得软化为"建议"。压力版从严:无作品集直接淘汰、无可访问链接则"作品集决策深度"维度不得超过 8 分;给高分却 why 全是缺口属于评分自相矛盾,应拒绝输出。

## 改写指引（禁编造铁律）
交互设计(压力版)改写遵循"禁编造"铁律,只把简历"已有"内容讲精准,严禁替候选人添加原句没有体现的能力、方法或工具名词。可改写:用了什么方法/工具、解决什么用户问题、覆盖到什么程度(流程数、异常场景数、设计稿数、用户量级),用精准设计动词替换模糊词(仅在简历已体现该动作时:"做了设计"→"梳理了主流程与 N 个异常场景的交互方案";"画了原型"→"输出高保真原型并补全边界/空/异常态交互说明";"做了用研"→"通过 N 次访谈提炼 X 痛点并对应到 Y 功能")。量化占位:仅在简历已暗示规模但缺数字处用 [具体数字] 占位(如"转化率提升 [具体数字]%""访谈 [具体数字] 名用户"),占位只补数字、绝不补能力。严禁把"协助/参与"夸大为"独立/主导";严禁添加原句没有的用研、Framer、AIGC、a11y 结论;严禁把课程项目包装成上线产品。缺失能力一律走 gap_advice(缺洞察→建议补关键痛点洞察、缺验证→建议补可用性测试或上线数据、缺异常态→建议补全状态矩阵、缺 Demo→建议做可交互 Demo、缺 a11y→建议标注对比度与触控尺寸),不写进改写句。original 必须是简历原文一字不差。

## 本土惯例与硬规则
【出局级硬规则(直接淘汰,优先核查)】无作品集＝直接淘汰(交互岗 100% 要求);作品集链接失效/网盘需申请权限/加载极慢＝大概率跳过,必须公开可访问、秒开;英文作品集投国内校招＝劝退概率极高,必须出纯中文版;简历与作品集揉一起且超 20MB＝减分(字节明确强调"分开")。【格式偏好】简历一页 A4、纯中文、信息优先于设计感;作品集 PDF 为首选主体、10MB 内、30-40 页;简历与作品集务必分开两个文件。【证书与背景优先级】国内几乎无通用职业资格证书被当硬指标;有含金量的是竞赛奖项(红点/IF 学生奖/NCDA 国赛/米兰设计周中国高校展);心理学/计算机/HCI 交叉专业被腾讯、百度等明确列为"专业优先",清华美院/央美/江南大学/同济等院校背景有隐性加分,但大厂官方口径"不看出身只看能力",多专业背景均有录取案例——不应因非设计科班扣分。【加分项】知名互联网公司实习、参与实际上线的商业产品、可交互 Demo、前端基础(HTML/CSS/JS 或 Framer 代码原型)、AIGC 工具使用经历。【反信号】简历花里胡哨但信息密度低;作品集套模板堆 Mockup;只有课程作业无任何实战;实习描述模糊只写"参与了产品设计";用进度条/雷达图自证工具力。
