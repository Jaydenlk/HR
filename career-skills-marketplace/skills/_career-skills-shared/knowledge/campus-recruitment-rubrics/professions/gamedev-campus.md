# 游戏开发（游戏开发 · 校招(融合版)）

> 校招职业标尺 · 难度档：`standard` · 预设ID：`gamedev-campus`

## 五维评分标尺（权重之和 = 100；score 封顶各维满分，total_score = 各维之和）

### 1. 项目作品完成度与工程闭环（满分 28）
- **好的样子**：至少1个完成度高、能抗住30分钟深挖的可玩Demo或可运行项目(跑教程起步可以,但必须有自己的改造);每个项目讲得清「技术域→要解决的问题→怎么取舍→量化结果」全链路,例如「移动端延迟渲染:在 Adreno 650 上把带宽占用降低40%」而非「基于 OpenGL 的渲染引擎」;GitHub 有真实持续提交记录(不是一次性上传),引擎/图形岗附渲染前后对比图与 Profiler 数据。
- **应届证据**：可玩 Demo 的视频/截图放进作品集;GitHub/Gitee 有跨越数周的多次 commit;项目描述带量化指标(帧率从X提到Y、DrawCall从X降到Y、带宽降低Z%);GameJam(Global Game Jam/Ludum Dare)完整参赛作品;在 Steam/TapTap 发布过可玩游戏(极稀缺、效果显著);笔试编程题全 AC 截图。
- **常见缺失 / 反模式**：项目全程照抄视频教程、GitHub 一次提交传完、没有任何个人改造;或只有设计文档没有可执行版本与视频,无法自证真做过。【反模式·教程搬运工:整个项目跟着视频敲、一次性传 GitHub,面试官追问「这块你改了什么、为什么这么改」当场失语】

### 2. 计算机基础扎实度(数据结构/算法/OS/计网)（满分 24）
- **好的样子**：数据结构/算法、操作系统、计算机网络三门都能从定义延伸到场景,而非只背八股;米哈游 JD 第一条即「具备扎实的计算机基础」。大厂笔试为 ACM 模式(需自行处理输入输出),能在限定时间内 AC 中等及以上算法题;OS 的内存布局/进程线程/调度能被 C++ 八股一路追问下去仍接得住。
- **应届证据**：ACM/ICPC 区域赛、蓝桥杯省级及以上获奖(最强直接信号);洛谷/AcWing 的 ACM 模式刷题量与排名;408 核心科目(尤其 OS、数据结构)成绩突出;笔试编程题全部 AC 的记录;OS/计网/数据结构相关的课程项目或博客。
- **常见缺失 / 反模式**：只刷 LeetCode 核心模式没练 ACM 自处理输入输出,大厂笔试第一轮直接被过滤;OS/计网/数据结构无任何项目或课程支撑,只会背定义。【反模式·八股背诵机:虚函数表会背、TCP三次握手会背,一句「为什么这么设计」就卡壳,知其然不知其所以然】

### 3. C++ 语言深度（满分 20）
- **好的样子**：C++ 是客户端/引擎/服务端三岗核心语言,一面普遍从 C++ 八股切入再往底层挖 OS(米哈游面经:从虚函数表问到内存结构)。好的样子是有用 C++ 独立完成的项目(非 Python/脚本包装),能讲清内存管理、多线程、STL、对象模型并往深处挖,读过《C++ Primer》《深度探索 C++ 对象模型》且能在面试中引用。
- **应届证据**：GitHub 上有以 C++ 为主语言的项目(渲染器、小型引擎、服务端模块、Ray Tracing);项目描述自然带出内存/多线程/对象模型且经得起追问;能写出「手写对象池规避频繁 new/delete」这类底层取舍;C++ 相关源码阅读或技术博客。
- **常见缺失 / 反模式**：技能栏突出 Java/Spring/Python,C++ 只在「了解」一栏,给面试官「转行者/外包气质」印象;或写「熟悉C++」但项目全是脚本调用、答不出虚函数表与内存布局。【反模式·Java气质C++:简历主体是 Java/Web 那一套,C++ 只是凑数,投引擎/客户端岗一眼被划为「非科班转行」】

### 4. 引擎使用与改造深度（满分 16）
- **好的样子**：客户端岗硬需求、引擎岗看「改造能力」。大厂客户端一面会问 DrawCall、UI 动静分离、AssetBundle、热更新,好的样子是写清具体模块:Unity 写到 UI 系统/动画系统/ScriptableObject/资源管理/Shader,UE 写到蓝图+C++ 混合、Gameplay 框架、自定义 Pass;引擎岗能体现「魔改 UE/Unity 渲染管线」而非只调 API——改过什么 > 用过什么。
- **应届证据**：项目里点名具体引擎模块与解决的问题(「用 AssetBundle 做热更新,包体从X降到Y」「自定义 UE 渲染 Pass 实现描边」);Profiler 调优截图;蓝图+C++ 混合工程;改造引擎源码或渲染管线的真实记录。
- **常见缺失 / 反模式**：技能栏只写「熟悉 Unity 开发」却不点任何模块,等于无效信息;只会拖蓝图/调 API,没有任何改造与底层理解。【反模式·熟悉Unity仔:简历就一句「熟悉Unity/UE」,问到 DrawCall 怎么降、AssetBundle 怎么组织就空白,大厂普遍认为引擎可入职后学、不改造=不加分】

### 5. 图形学与渲染知识（满分 12）
- **好的样子**：引擎/图形渲染方向核心门槛,客户端为加分项。GAMES101 现在只是「及格线」,光会101无法构成优势;好的样子是 GAMES101(入门)+ GAMES202(实时渲染)至少完成一个,能讲清渲染管线顺序、透明物体排序、PBR、Shadow Map、Deferred Rendering 并追得住性能权衡,有 Ray Tracing 项目(《Ray Tracing in One Weekend》是低门槛起步),项目描述写清「为什么选此方案」而非只写「我实现了XXX」。
- **应届证据**：GAMES202/RayTracing 项目附渲染截图与 Profile 对比;项目描述出现具体取舍(「为什么用 Deferred 而非 Forward」);用 RenderDoc/Profiler 定位渲染 Bug 的过程;图形技术拆解博客;论文或导师科研项目(图形方向加分明显)。
- **常见缺失 / 反模式**：堆「GPU Driven Rendering / Clustered Lighting / Mesh Shader」等术语却无量化结果、无取舍说明,AI 时代面试官无法判断真假;或简历只写「学过 GAMES101」就当核心竞争力。【反模式·技术词堆砌症:把最唬人的渲染名词全列上,却讲不出一个数字、一次取舍,越堆越像没真做过】

## 打分解释规则（每维 why 必须落到简历事实；命中反模式直接点名；严禁泄漏"满分的X%/扣X分"等内部计算）
每个维度必须给出 why,且分数与 why 严格一致:① 先指出简历中具体命中/缺失的事实(可玩 Demo 是否抗深挖、GitHub 是否有持续 commit、项目是否讲清「技术域→问题→取舍→量化结果」全链路、是否有帧率/DrawCall/带宽等数字、C++ 是否为主语言并带内存/多线程/对象模型、引擎是否点到具体模块或改造、图形是否 GAMES202/RayTracing 且写清取舍、ACM/蓝桥/实习是否真实可核),写进 evidenceFound/gap;② 说明在校招游戏开发语境下该维度为何重要(游戏岗考的是「你做过什么、为什么这么做、效果如何」的思维链路,30分钟深挖与从 C++ 挖到 OS 的连环追问最易暴露真实水平;CS 基础是大厂 ACM 模式笔试第一道关卡);③ 命中反模式直接点名(如「教程搬运工」「八股背诵机」「Java气质C++」「熟悉Unity仔」「技术词堆砌症」),不得空泛。严禁因学历或技能词覆盖广而给高分——双非但有抗深挖 Demo+量化结果应高于 985 只有课程作业;技能栈堆得多但项目用不上、引擎只写「熟悉」必须扣分;岗位方向错配(用图形项目投 C++ 偏重的游研岗、或用 Java/Web 投引擎客户端)要在对应维度明确降分。

## 改写指引（禁编造铁律）
改写只能基于简历「已有」内容做精准化重组:把含糊的项目/实习句讲精准(用了什么引擎/语言/图形技术、解决了什么渲染或性能或玩法问题、量级多大),用精准动词(实现/优化/重构/魔改/接入/压测)与可量化指标增强可信度——帧率(从X提到Y FPS)、DrawCall(从X降到Y)、带宽/内存占用降低Z%、包体大小、加载耗时、并发在线数等。只在缺数字处用「具体数字」占位,并在 reason 说明「建议补充真实 Profiler/工具读数」。严禁替候选人添加原句没有体现的能力或技术名词——简历没写自定义渲染 Pass 就不能改出「魔改管线」,没写 RenderDoc 就不能编出调试细节,没写 GAMES202 就不能虚构实时渲染能力,没写 C++ 内存管理就不能加;凡简历没有的能力一律走「建议补充(gap_advice)」而非编造,更不得把「参与/协助/跟教程做」夸大为「独立/主导/从零设计」。original 必须是简历原文一字不差。特别警示:量化数字不得超出硬件物理极限(如某移动 GPU 的填充率),占位只提示候选人填真实工具读数。

## 本土惯例与硬规则
中国校招游戏开发本土惯例核查:① 出局级硬规则——大厂(腾讯/米哈游/网易)头部岗位实际以 985/211 为主,非科班+双非需用极强作品集补偿(面经共识,非官方公示);笔试为 ACM 模式,需自行处理输入输出,只练 LeetCode 核心模式不够,必须刷洛谷/AcWing;毕业时间卡死,超出年份窗口直接拒;简历严格 1 页 A4,超出视为不会整理;无可运行 Demo 或只有设计文档的项目近乎不计入评分。② 岗位方向匹配——引擎/客户端/渲染三岗面试重点不同,严禁同一份描述混投;投引擎岗要有图形+C++,投客户端要有引擎使用深度,用游研语言投引擎岗或反之是明确反信号。③ 证书/竞赛优先级——ACM/ICPC 区域赛及以上 > 蓝桥杯省级 > 技术类论文发表 > 国家级游戏创作大赛 > Unity 认证 > 课程证书(近乎无效);Unity 官方认证在游戏大厂 HR 眼中权重极低,远不如一个有量化结果的项目;技术岗 GPA 几乎不问、背调也不看。④ 格式——中文主体、技术词保留英文(DrawCall/Shader/Profiler),雅黑或思源宋,1 页 PDF;GitHub 主页必须存在且有活跃记录(被点开率约30%,空主页=减分);引擎/图形岗强烈建议作品集附渲染截图+Profile 对比数据。⑤ 反信号——多岗投递描述一模一样(显无针对性)、引擎/客户端岗突出 Java/Spring/Python(转行者印象)、个人评价写「吃苦耐劳/责任心强/沟通能力强」等通用空话(等同空白)、完全无实习经历直冲大厂(共识路径是小厂→中厂→大厂)。⑥ 加分项——大厂或知名中厂实习是最强单项加分、论文/导师科研项目、GameJam 完整作品、内容有深度的技术博客(知乎/GitHub Pages)、在 Steam/TapTap 发布过可玩游戏;米哈游/叠纸/鹰角等文化属性强的厂会真实考察玩家深度(品类/名称/时长/成就),个人兴趣处应据实写出代表性游戏与玩家深度——这是真实门槛而非噱头,但腾讯/三七互娱不强要求。
