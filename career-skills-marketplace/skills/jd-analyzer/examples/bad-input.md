# 示例：非 JD 输入 → 返回 error

## 场景

用户误粘贴了一篇科技新闻，不包含任何职位描述内容。

## 输入

```json
{
  "jd_text": "据报道，某大型科技公司今日宣布完成 C 轮融资，融资金额达 5 亿美元。本轮融资由多家知名风险投资机构领投，公司估值突破 30 亿美元。该公司成立于 2019 年，主要从事人工智能基础设施研发。业内人士分析，此次融资将加速其产品商业化进程。"
}
```

## 输出

```json
{
  "skill": "jd-analyzer",
  "confidence": "insufficient",
  "error": {
    "type": "non_jd_input",
    "message": "输入内容不是职位描述。请粘贴包含岗位名称、职责或任职要求的招聘 JD 文本。",
    "evidence": "检测到内容为融资新闻（含「融资」「估值」「风险投资」等关键词），未发现职位/职责/要求等 JD 特征"
  },
  "risk_count": 0,
  "implicit_count": 0
}
```

## 说明

- `confidence: "insufficient"` 时不输出 `parsed_jd` 字段
- `error.evidence` 说明判断依据，降低误判风险
- 不从新闻内容中推断任何职位信息

## 边界说明

以下输入**不**应返回 error，应返回低置信度结果：

- 「招聘 Java 工程师，有意联系」（虽然极短，但有 JD 特征）
- 「要求本科，3 年经验，北京」（有要求描述，属于超短 JD）
