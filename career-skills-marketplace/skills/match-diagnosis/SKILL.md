# match-diagnosis — 简历与 JD 匹配诊断技能

## 核心任务

对比用户画像与目标职位 JD，从多个维度评估匹配程度，给出有区分度的评分、差距分类和改进建议。

**评分铁律：分数必须有区分度。** 不允许出现所有用户都落在 60-80% 区间的趋中现象。

---

## 五维评分模型

| 维度 | 权重 | 说明 |
|------|------|------|
| 技能匹配（skills） | 30% | 技术技能与 JD 要求逐项对比，区分"完全匹配/部分匹配/缺失" |
| 经验相关度（experience） | 25% | 工作经历的行业、职责、年限与 JD 要求的匹配程度 |
| 教育背景（education） | 15% | 学历层次、专业相关性是否满足 JD 要求 |
| 岗位目标（role） | 15% | 职业发展轨迹与目标岗位的一致性（如应届生投高级岗） |
| 隐性约束（constraints） | 15% | 工作地点、薪资预期、工作性质（全职/兼职）等实际约束 |

各维度得分加权求和得到总分（0-100）。

---

## 评分校准标准

评分必须能真实区分候选人质量，严格对照以下区间：

| 区间 | 标签 | 含义 |
|------|------|------|
| 85-100% | 强匹配（perfect_fit） | 几乎全部要求满足，建议直接投递 |
| 70-84% | 高匹配（strong_match） | 主要要求满足，小部分有差距 |
| 50-69% | 中等匹配（moderate_match） | 核心技能有匹配，但有明显差距 |
| 30-49% | 弱匹配（weak_match） | 部分相关，投递风险高 |
| 0-29% | 不匹配（no_match） | 背景与岗位根本不符，不建议投递 |

**校准规则**：
- 完美匹配所有要求 → 85-100，不要因为"保守"给70
- 有严重必须项缺失（JD 明确标注 required） → 直接不超过 50
- 工作年限差距超过 50% → 最多 65
- 教育背景严重不符（JD 要求硕士，用户只有高中）→ 教育维度得分 0-5

---

## 差距分类

每个差距项（gap）按以下类型分类：

| 类型 | 含义 | 例子 |
|------|------|------|
| `quick_fix` | 短期可弥补（1个月内） | 缺某个工具技能但有相关基础 |
| `needs_time` | 中期可弥补（3-12个月） | 缺乏某领域经验但有基础 |
| `hard_mismatch` | 难以弥补的根本性差距 | 工作年限严重不足、专业完全无关 |
| `uncertain` | 无法判断（信息不足） | 数据缺失无法评估 |

---

## 置信度规则

置信度反映评分的可靠程度：

| 条件 | 置信度 |
|------|------|
| 用户画像 + JD 均信息充足 | `high` |
| 其中一方信息不足（如 JD 过于简短）| `medium` |
| 双方信息均不足 | `low` |
| 关键信息完全缺失（无法评分）| `insufficient` |

置信度为 `insufficient` 时，必须明确说明缺失的具体信息，不产生评分。

---

## 输入要求

本技能**同时需要**两份数据：

| 参数 | 必须 | 说明 |
|------|------|------|
| `user_profile` | 是 | 用户结构化画像 |
| `jd_analysis` | 是 | 目标 JD 结构化分析 |

两者缺一不可。若只有其中一个，置信度为 `insufficient`，不产生评分。

## 禁止行为

1. **禁止趋中打分**：不允许对所有用户给出 60-80% 的分数范围
2. **禁止无依据的高分**：不能因为用户"看起来不错"就给高分
3. **禁止忽视 required 项缺失**：JD 中标注 required 的项目缺失，总分不能超过 50
4. **禁止虚假安慰**：差距是 hard_mismatch 就要如实标注，不能改成 needs_time
5. **禁止无视置信度**：信息不足时必须降低置信度并说明，不能假装数据充分

---

## 隐性约束处理

隐性约束（constraints 维度）包含但不限于：

- **工作地点**：JD 要求北京，用户在上海 → 明确标注，不能假装没有这个约束
- **工作性质**：实习 vs 全职不匹配 → hard_mismatch
- **语言要求**：JD 要求英文工作环境，用户未提及英语能力 → uncertain
- **工作制**：JD 要求接受 996 或弹性工时，而用户有明确限制 → 标注

这些约束往往比技能差距更影响录用决策，必须如实呈现。

## 产品原则适用

本 skill 遵循 `../_career-skills-shared/policies/product-principles.md` 中的两项核心原则。

### 信息不足时 (Ask-before-judging)
- 当 `user_profile` 或 `jd_analysis` 任一缺失时，视为信息不足
- 信息不足时不能输出精确匹配分数（`overall_match_pct` 和 `dimension_scores`），因为缺少对比基准，任何数字都是幻觉
- 低置信度时只给出维度级别的定性评估（如「技能维度：无法评估，缺少 JD 技能要求」），不产生加权总分
- 追问最小必要问题：缺简历时追问「请提供您的工作经历和技能列表」；缺 JD 时追问「请提供目标职位的职位描述」

### 出处-思考-观点 (Source-Reason-Opinion)
- Source: 每个维度得分必须引用 `user_profile` 和 `jd_analysis` 中的具体字段作为对比依据
- Reasoning: 在 `dimension_scores[].analysis` 中体现「用户有 X，JD 要求 Y，因此得分 Z」的推理过程
- Opinion: `gap_classification` 中每项差距标注 `gap_type`，`improvement_suggestions` 标注 `priority` 和 `estimated_effort`，区分已知事实与推断建议
