# 示例 02：背景严重不匹配（后端工程师投递市场运营岗位）

## 场景说明

用户是纯技术背景（Java 后端工程师），投递某互联网公司的用户增长运营岗位。两者背景差异极大。本例演示技能在面对严重不匹配时的诚实评估，不强行改写。

---

## 输入

### resume_text
```
陈明，Java 后端工程师，3年经验
华东师范大学 计算机科学 本科 2021年毕业

工作经历：
2021.07 - 至今 | 某电商平台 | Java 后端工程师
- 负责商品管理系统后端开发
- 参与数据库性能优化
- 使用 RabbitMQ 处理异步消息

技能：Java、Spring Boot、MySQL、Redis、Linux
```

### jd_text
```
岗位：用户增长运营专员（某互联网公司）
岗位职责：
1. 制定用户增长策略，执行拉新、留存、促活运营活动
2. 分析用户行为数据，输出运营报告，驱动产品优化
3. 管理社群运营，策划内容，维护 KOL 关系
4. 跨部门协作推进用户增长项目

任职要求：
- 2年以上互联网运营经验（必须）
- 熟悉用户增长方法论（AARRR 等）（必须）
- 有数据分析能力，熟悉 Excel/SQL（加分）
- 优秀的文案撰写和活动策划能力（必须）
- 有社群运营经验者优先
```

---

## 输出

### 诚实评估

**匹配度评估：严重不匹配（估计重叠度 < 15%）**

用户背景（Java 后端工程师）与目标岗位（用户增长运营专员）存在根本性的领域差异。以下是诚实分析：

**JD 必须项 vs 用户现状**：

| JD 要求 | 用户现状 | 可弥补性 |
|---------|---------|---------|
| 2年以上运营经验 | 无运营经验 | 改写无法弥补 |
| 熟悉 AARRR 增长方法论 | 原材料中未提及 | 改写无法弥补 |
| 文案撰写能力 | 原材料中未提及 | 改写无法弥补 |
| 活动策划经验 | 原材料中未提及 | 改写无法弥补 |

**可迁移的技能（真实存在于原材料中）**：

1. **数据分析基础**：参与数据库性能优化，说明有 SQL 能力。JD 加分项中提到"熟悉 SQL"，这是真实的可迁移优势
2. **技术背景理解产品**：电商后端经验使其能快速理解平台技术逻辑，与技术团队沟通无障碍

### 建议（代替强行改写）

1. **短期补充**：参加运营相关课程或项目，获得真实的运营实践经验
2. **过渡方向**：可以考虑技术运营（Technical Operation）或增长黑客（需要技术+数据分析）岗位，与用户背景更接近
3. **内部转型**：若目前公司有运营岗位，可申请内部转岗，积累运营经验后再投外部岗位

### 若用户坚持要我改写

我仍然无法将"负责商品管理系统后端开发"改写为运营经历。

改写不能改变经历本质，只能优化表达方式。如果原材料中没有运营经历，没有任何合法的改写操作能填补这个空缺。
