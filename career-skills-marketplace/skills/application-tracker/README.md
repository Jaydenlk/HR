# application-tracker — 投递状态追踪

## 概述

分析求职投递记录，生成漏斗视图统计，识别需要跟进的投递和疑似幽灵岗，帮助候选人掌握求职整体进展。

## 适用场景

- 多条投递后想了解整体漏斗健康度
- 忘记哪些公司需要跟进
- 某个投递长时间没消息，判断是否为幽灵岗
- 每周例行回顾求职进展

## 投递状态

| 状态 | 含义 |
|---|---|
| `submitted` | 已投递，等待筛简 |
| `in_review` | 简历已被查看 |
| `interview_scheduled` | 已约面试 |
| `interviewing` | 面试进行中 |
| `offer` | 已获 offer |
| `rejected` | 已被拒绝 |
| `withdrawn` | 主动撤回 |
| `ghost` | 已确认幽灵（手动标记） |

## 幽灵检测规则

- `submitted` 状态超过 **14天** 无更新 → `stale` 提醒
- `in_review` 状态超过 **21天** 无更新 → 疑似幽灵
- 面试后超过 **7天** 无结果通知 → 疑似幽灵

## 跟进建议时机

1. 面试后24-48小时：发送感谢信（高优先级）
2. 超过阈值无回音：发送一次性跟进（中优先级）
3. 简历被查看后7天无消息：轻量问询（低优先级）

## 限制

- 不推测未提供的状态，缺少状态时默认 `submitted`
- 缺少日期时无法做幽灵检测，在 `cannot_determine` 中说明
- 统计数据基于用户实际记录，不推断未记录的投递

## 依赖

无（独立技能，不依赖其他技能）
