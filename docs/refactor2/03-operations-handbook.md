## 一、配额作战模型(最重要的一章,教训最贵)

### 1. 任务切片纪律(事前防)
- **单 agent 单窗口预算红线 ≈150k token**。impl 预估超过就必须**拆阶段**,每阶段独立 commit。实测教训:t4-s0-d1 的 impl 单趟 240k/360k,连撞 3 次 session 上限,烧掉两个窗口才靠抢救性提交保住成果。
- 大 impl 的正确形态:阶段 A(后端核心)commit → 阶段 B(联动面)commit → 阶段 C(前端/测试)commit。**commit 是唯一可靠的存档,working tree 里的一切都可能随中断蒸发。**
- 紧配额时段(见 §1.3)**不许启动大 impl**,小活(验证/审计/文档)优先。

### 2. WIP 抢救标准流程(事后救,实操验证过)
症状:impl 撞限中止,worktree/分支有未提交改动。
```
① 立即落盘:git -C <worktree> add <相关路径> && git commit -m "wip(<task>): ...(未过质量门,防配额中断丢失)"
② 双保险快照:git -C <worktree> diff <base>..HEAD > E:\Agent program\coach-wt\_snapshots\<task>-<时间>\...(含未跟踪新文件复制)
③ 记忆断点记录:分支/commit/快照路径/成色判断
④ 恢复后:验证优先于重跑 —— 先派验证代理跑全部
