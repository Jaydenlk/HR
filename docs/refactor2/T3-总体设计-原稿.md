## 一句话定义（修订版）

> 面向中国应届生的**结构化职业知识系统**——它既是**给用户读的职业百科**（30 秒建立认知、看清一个职业到底是什么、和相邻职业差在哪、怎么入行），也是**给推荐系统查的职业知识库**（推荐系统消费它来做职业匹配与"择岗"，且因为内容诚实、具体、敢说代价，匹配结果对用户有"确实懂我、确实适合"的说服力）。它不是职业名词解释，也不是 JD 摘要库。

这个定义有两个消费面，是同一份知识的两种用法，不是两份东西——这正是下面架构要解决的核心。

## 一、总体架构 Map：三平面 + 两根轴

### 1. 核心：结构主干是唯一事实源

整个百科围绕一个中心对象转——**结构主干（structured skeleton）**，每个职业一份，是该职业的**唯一权威表示**。它有三个平面（见架构图）：

- **证据层（后台）** —— 三锚点源 + 断言级蕴含校验 + 置信/缺口标注。只供溯源，**永不以叙述形式进前台**。
- **结构主干（中层，唯一事实源）** —— 生成与校验**只作用在这一层**。它是被生产、被质检的唯一对象。
- **前台双渲染（上层）** —— 从主干派生出两种输出：**百科散文**（给人读）与**结构化字段**（给推荐系统查）。散文是主干校验完之后的一次性廉价重排，不再单独校验。

**为什么必须这样设计**：我们之前撞上的三个问题——前台被审计噪音污染（`Stage5`/`A1A2A3`/`null红线自查` 塞进正文）、内容"不像百科"（像证据堆叠而非职业解释）、以及 token/ROI 失控——**是同一个病的三张脸**：把"给审核员看的审计过程"当成了产品本身，在生成它、反复读它、反复校验它。三平面把这三样一次切开：审计只存在于证据层，产品是主干，前台是主干的廉价渲染。

### 2. 结构主干 = 固定骨架 + 微调槽

主干内部分两类槽位，把"通用"和"每职业微调"在结构上就分开（这是统一文体、堵住"边生成边搭骨架"的地方）：

**A. 固定骨架（8 层，所有职业完全一致，不许各写各的）**

| 层 | 内容 |
|---|---|
| 定位层 | 一句话定位 / 解决什么问题 / 为什么这个职业成立（社会分工意义，非 JD 定义） |
| 坐标层 | 职业族 → 行业场景 → 相邻职业(≥3) → 上游/下游 |
| 边界层 | 与 ≥3 个相邻职业的真实差异（百科最核心模块） |
| 实操层 | 真实工作流(日/项目/周期) / 典型产出物 / 工具系统 / 考核指标 |
| 入行层 | 对口专业 / 非对口转入 / 校招信号 / 简历有效经历 / 看似相关实则无用 |
| 差异层 | 行业差异 / 组织性质差异 |
| 门槛层 | 隐性门槛 / 常见误解（客观事实性的：代价、淘汰、收入结构） |
| 趋势层 | AI 影响（被替代 / 被增强 / 新技能） |

**B. 微调槽（骨架里预留，每职业只填一点点，占比压到很小）**

微调**不是**让它自由发挥重写结构，而是在固定骨架里填两个受控参数：

- **`axis`（差异主轴，枚举字段）**：这个职业的"周期"按什么走。产品岗=产品生命周期，制度岗=准入周期(规培/法考)，农业岗=作物生育期。做成枚举后，`project/quarterly` 语义不统一的问题当场消失——不是每条自己解释周期，是从固定选项里选一个。
- **`domain_specifics`（专有槽，封顶几条）**：只装该职业真正独有的东西（临床的规培证、AIPM 的置信阈值/降级策略）。超出封顶一律回落到固定骨架。

> **从骨架里彻底移走**（这些让稿子"不像百科"、也在重复烧 token）：`source_ref / A1A2A3 / entailment-log / Stage5 / null红线自查 / Dim1分数 / inferred前缀` 全部下沉到证据层。

### 3. 上层组织轴：taxonomy（词条从哪来、怎么编排）

主干之上是"这些职业如何被组织成词条"的分类轴：

- **L0 板块**（6 类：通用职能 / 工程技术 / 产业专业 / 公共制度 / AI 新兴 / 创意服务）→ **L1 职业族** → **L2 行业场景** → **L3 交叉具体岗位**（"工业软件产品经理 ≠ 互联网产品经理"，同名实异，这层是用户真正查的主体）。
- **横切维度 = 企业性质**（民企/外企/央企/国企/政府/事业单位/法院检察院/高校科研/创业）。对普通企业岗做横切标签；对**制度型岗位（公务员/法院/事业/高校）组织性质本身是主入口**，不只是标签。
- **三锚点**：**真实校招 JD = 主源**（最新、最贴中国，且只能撑 A 层事实；隐性门槛类内容本就是 B 层推断，不假装有 JD 出处）；**O*NET = 字段骨架**；**大典 2022 = 负清单/查漏锚点**（不镜像它的 1636 细类）。
- **规模**：全库 **700–800 顶天**。萝卜坑不入库；考公考编收敛进一个母条；政治/敏感内容杜绝。

### 4. 生产轴：ROI 流水线

主干由一条流水线生产（详见第三部分）。一句话：**抓取 → 主干生成 → 断言级蕴含分诊 → 脚本确定性检查＋合并语义审 → 定点补丁(封顶) → Opus 收口**。

## 二、骨架 + 微调讲清了什么：用户能了解到什么

固定骨架的 8 层，逐层对应用户读完能拿到的东西：

| 骨架层 | 用户读完知道 |
|---|---|
| 定位层 | 这职业是什么、解决什么问题、为什么在 AI 时代/社会分工里成立（30 秒建立心智模型） |
| 坐标层 | 它在职业世界里站哪、旁边是谁、上下游是谁 |
| 边界层 | 它和 AIPM/算法PM/FDE/传统PM 这类"看着像"的岗到底差在哪 |
| 实操层 | 实际每天/每个项目/一年在干什么，产出什么，用什么系统，凭什么算合格 |
| 入行层 | 什么专业对口、非对口能不能进、校招看什么、简历上什么有效、什么看着相关其实没用 |
| 差异层 | 同一个岗在不同行业、不同性质单位（国企/外企/民企/政府）的真实差异 |
| 门槛层 | 真实代价、淘汰机制、收入结构、常见误区（不只光鲜面） |
| 趋势层 | AI 会替代它哪些、增强哪些、3 年后要补什么能力 |

**用户/系统在这里能完成三件事：**

1. **建立认知（30 秒）** —— 靠定位层 + 坐标层。
2. **比较职业** —— 靠边界层 + 坐标层。**没有相邻对比，就不是百科、只是介绍**；每个词条强制与 ≥3 个相邻岗做差异。
3. **规划入行** —— 靠入行层 + 趋势层。

> **关于"匹配判断"的定位（重要）**：判断"这个岗**适不适合你**"这种**主观匹配**，主要是**推荐系统消费知识库时**做的事（体现在"大模型利用知识库的 prompt 加强"那一层），**不是百科正文的核心占比**。百科门槛层里带**一句客观的"哪类人不适合"**就够；`fit_profile / who_should_not` 这类主观匹配内容，在**推荐系统输出侧**占一定板块，但也**不是最核心内容**，更不该反过来主导百科的结构。

**双重消费者，一份主干：**

- **人读（百科散文）**：把主干重排成好读的职业解释，证据链藏在后台、需要时才展开一句"来源说明"。
- **机器查（结构化字段）**：推荐系统查的是主干的**结构层枚举/标签**（技能、渠道、学历门槛、AI 轨迹…），不是散文。**推荐系统不能查散文，只能查字段**——所以结构层是那个"懂我"效果的技术前提。而"懂我"的说服力来自内容诚实、具体、敢说代价，这是护城河的自然结果，不是额外堆出来的话术。

## 三、经济效益前提下如何保质

### 核心洞察：骨架焊死是 ROI 第一杠杆

ROI 失控的**根因不是流水线参数没调好，是骨架没搭全**——因为骨架没定死，Claude Code 在**边生成边自己搭骨架**：五份稿子文体各不相同（一份像 JD 报告、一份像制度解释、一份像修复日志），`project/quarterly` 每份语义都不同，**每条词条都要重新协商一遍"这个职业该长啥样"**。这种反复协商，就是 token 烧穿的真正来源。

**骨架一旦焊死成常量，生成退化成"往固定槽位填值 + 少量微调"，发散和重复付费自然塌下去。** 所以骨架不是和 ROI 并列的另一个问题，**它是 ROI 的上游**。这是第一杠杆，下面的流水线优化都是它的下游。

### 质量和 ROI 是同一个机制

一句话：**把审查放在断言级 + 一切从固定骨架派生**。这一条同时压成本、同时保质。具体机制：

1. **主干-only 生成** —— 生成只产出结构主干（字段+值+每条断言的 source_ref+B 层置信），**不产散文、不产自查表、不产 QC 叙述**。
2. **散文是廉价一次性渲染** —— 主干校验完之后，把已验证事实重新排版即可，**不再校验**。证据包只是主干的溯源侧表，不再被叙述成正文、不再被重读。
3. **断言级蕴含（配对判断，不搬源池）** —— 校验模型只判 `(断言, 引用源摘录)` 撑不撑得住；失败就把断言**移到 B 层标推断、或删掉，不重生成任何东西**。
4. **杀掉回炉循环** —— 换成"生成主干 → 蕴含分诊(移/删) → 一次审核标出要修的具体字段 → 只定点补那几个字段(封顶 1–2 轮) → 完"。**永不整条重建。**
5. **确定性检查移出 LLM** —— 词汇密度、套话黑名单、字段完整度是纯字符串/计数，**用脚本跑、免费**；只有语义类（可核实性、隐性门槛是否只说光鲜、换名可区分）留给**一次合并的** LLM 审。
6. **风险分级** —— 低危字段（一句话定位、产出物清单）轻检即过；只有**高危字段（具体数字/阈值/规范/跨性质具体差异）才上蕴含 + 对抗审核**。
7. **收敛 fan-out** —— 把"每条每轮各起一个 agent"的散射，合并成 一次抓取 + 一次主干生成 + 一次蕴含分诊 + 一次合并语义审 + 封顶定点补丁，Opus 全局收口一次。跳数少 → 上下文重传少 → 直接治"发散程度太高"。
8. **每条预算护栏 + fail loud** —— 给每条词条设 token/步数预算，超了就停下报警（而不是无声烧到底），把"每条已验证词条的成本"当核心指标盯。

### 为什么这不牺牲质量（护城河如何被保住）

- **质量来自断言级溯源，不来自重生成循环。** 把一条词条从头重生成 N 次，并没有增加准确性，只是烧了 token——真正决定"不编造"的是每条断言过没过蕴含，而这一步被保留且强化了。
- **完整度靠固定骨架保证，是结构性的、免费的。** 每条词条都有全部 8 层，不靠昂贵的循环去凑齐。
- **风险分级把贵的审查用在真会出错的地方**（具体数字/规范/跨性质差异），而不是浪费在送分字段上——省钱的同时，火力更集中。
- **确定性检查（脚本）既更便宜、也比 LLM 更可靠**，因为它测的东西（密度、黑名单、完整度）本就是确定性的。
- **诚实红线在主干/断言级强制执行**（无源硬数据→null、B 层标推断、撑不住即降级/删），**与任何 ROI 裁剪无关**——护城河不会因为省钱而松动。

### 一个可盯的指标

**每条已验证词条的 token 成本。** 焊死骨架 + 上面 8 条落地后，它会从"每条几十万 token"量级掉下来。这个数就是"经济效益 vs 质量"是否真被同时解决的单一体检指标。
