# T3 内容生产 Prompt Playbook(草案,待用户确认)

> 缘起:回归5条试验田中,GPT 首轮 R3 产出 258 条占位空转证据(claim 全是"来源支持X字段"模板)。用户裁定根因=任务下发(prompt)问题。本 playbook = Claude(leader)与 GPT-5.6(codex-56,thread 019f6848-d800)复盘讨论的定稿草案,经用户确认后成为经济批/量产的 prompt 权威模板。
> 上位文档:t3-regression5-plan.md(流程与七裁决)/t3-codex56-review(闸语义)。

## 一、病因裁决(双方共识)

**一级真因**(结构性):
- A. "每个非null叶子至少一条evidence"——把验证任务框成填表任务,配额驱动;
- B. 格式规格(11字段)篇幅远超语义要求,且无正例;
- D. 自查只查数量(覆盖率)不查质量(对应性);
- **F.(GPT补)目标函数代理化**:模型优先优化最容易被检查的代理指标(JSON可解析/字段齐全/覆盖率满),语义真实性无人查=软要求;
- **G.(GPT补)没有"拒绝生成"的合法出口**:prompt 未把"无证据"定义为合法结果,模型把"验证不了"理解为失败→用占位/泛化/重复挂载维持结构完整。

**放大因素**:C. 大批量+可重入摊薄单条投入;E. 无反例黑名单("占位模板"未被列为违禁品)。

**GPT 自述的危险信号清单**(prompt 里出现即诱导走格式捷径):覆盖率词汇(每个/全部/不得遗漏/至少一条)、无合法失败状态、schema 多而样例无真实对应、自查只查数量、批量大而无抽样验收、无正反例、末尾反复强调格式而语义只有一句。

## 二、完成定义重写(P0,一切模板的核心)

```text
错误完成定义(旧):每个非 null 叶子至少有一条 evidence。
正确完成定义(新):每个叶子都有诚实的覆盖处置——
  要么:有真实证据支撑,生成 evidence(过四重校验:叶子逐字子断言/摘录原文定位/语义对应/verdict保守);
  要么:撑不住,回改 skeleton 该叶子为 null(合法且被表扬的出口,不是失败)。
宁可少覆盖,不得错配。语义真实性优先于覆盖率。
```

注:我方体系的"合法拒绝出口"= **null 降级**(闸设计本来如此),不新增 coverage_status 字段(见 §六调和)。

## 三、三层模板结构

- **L1 通用骨架**(所有职业共用):完成定义(§二)+铁律八条(claim=叶子连续逐字子串/摘录逐字来自源/directly_supported=源明确表达同一命题/无源即null/禁一段摘录批量挂载无关叶子/禁常识伪装源事实/真实性>覆盖率/批量是传输策略不是质量目标)+违禁形态黑名单(§五)+结构化自证要求(§四)+现有 11 字段契约与闸命令。
- **L2 职业档位参数**(四档,GPT 裁决从三档拆四档,采纳):

| 档 | 典型 | 源优先级 | 核心风险(prompt 内点名) |
|---|---|---|---|
| T1 强监管准入型 | 医师/律师/注册会计师 | 法规监管>执业标准>考试大纲 | 把法规要求误写成普遍事实;推理默认禁止 |
| T2 标准化专业技术型 | 护士/土木工程师/检验技师 | 职业标准>认证>技术规范>教材 | 技能清单拼成能力断言;同技术体系内允许有限归纳 |
| T3 企业通用职能型 | PM/HRBP/市场 | 多源交叉JD>能力模型>单一JD | **单个JD误写成行业共识**;跨源归纳必须标"常见/部分组织" |
| T4 新兴源稀疏型 | 智慧农业/碳管理 | 官方项目>多独立机构>行业报告 | 为覆盖率过度推断;"行业共识"式表述必须多源 |

- **L3 单职业槽位**(每职业只填):slug/老稿或源池路径/该职业特有语义陷阱 1-3 条(如 hrbp:"单个公司JD只能证明该公司的岗位期待")。L3 不得重复定义 schema/verdict/证据规则。

## 四、结构化自证(模板固定件,拒收条件硬化)

- 抽样:每批 1-5 条全量自证;6-20 条抽 5;>20 条抽 max(5,20%) 上限 10。**强制边界样本**:全部高危 directly_supported+全部重复 source_excerpt 挂载条+每种源类型至少一条。
- 自证格式(每条):leaf_text / claim_text / leaf_slice(机算切片)/ slice相等布尔 / source_excerpt / 支撑判断 / 一句话理由。
- **拒收条件(任一即整批拒,不许"大部分正确"抵消)**:切片不等/摘录源内无法定位/directly无对应/抽样现占位或元话语/同摘录挂无关叶子/自证摘要与明细矛盾/抽样不可复现或只挑好证的。

## 五、金样本+违禁形态(嵌入各阶段 prompt)

- R2 金样本:可验证完整命题的叶子(有动作有对象,单维度);违禁:'负责相关工作'类空转/一叶多维混装/标题名词充当内容/元话语。
- R3 金样本:claim_text=叶子文本切片(机算 leaf_text[a:b]===claim_text)+摘录明确表达同一命题+保守 verdict_reason;违禁:占位模板/"该来源支持X"元话语/同摘录挂无关字段/同义改写冒充切片/无摘录判 directly/全量 directly 零 null 降级(可疑信号)。
- R6 金样本:事实句绑定证据边界("单个公司的JD可以证明该公司的岗位期待,不能单独证明所有企业如此");违禁:无源精确数字/"研究表明"包装常识/"显然/毫无疑问/普遍"掩盖源不足/段尾升华总结陈词。

## 六、与现有焊死 schema 的调和(leader 裁决,不动 schema)

GPT 方案中以下建议**不采纳为 schema 变更**,降级为过程机制(理由:evidence 11 字段契约+闸已实现并实战加固,量产前动 schema 成本与风险大;骨架 schema 焊死=用户审批事项):
1. `coverage_status` 叶子状态枚举 → 用 **null 降级**等价实现(unverified=叶子写null);批间交付一份"叶子处置表"(工作产物,不入库)记录每叶子 supported/null化+原因。
2. `source_span`(摘录在源内定位)→ 老稿源是摘录集不是全文,不可行;等价物=**摘录必须逐字来自 sources.json 既有摘录或新抓源原文**+R5 抽查比对(现行做法,保留)。
3. `confidence`/`review_flags` 字段 → 不入库;高危复核由闸的高危规则+R5 对抗审承担。
4. 双 span 中的 leaf_span = 现有 span_start/end(闸已实现逐字绑定),无需新增。

## 八、证据参考基准(用户 2026-07-16 定向指示,量化条款为草案数值待确认)

### 8.1 职业成熟度定级(先定级,再路由源;定级判据必须量化,禁用"初步规模"类裸定性词)
| 级别 | 量化判据(草案) | 源路由 |
|---|---|---|
| **国内稳定型**(如产品经理/HRBP) | 国内 TOP10 大厂中 ≥5 家近 12 个月有公开在招 JD,且连续 2 个校招季持续出现 | 现状层(定位/实操/入行/门槛)以**国内 TOP10 大厂 JD**为基准源+国内官方文件;湾区源仅作趋势层参考 |
| **国内初步规模型** | TOP10 中 3-4 家在招,**或**主流招聘平台(BOSS/猎聘/智联)可检索 ≥20 家独立雇主在招 | 国内源为主,湾区源补趋势与方法论;词条差异层如实写国内成熟度 |
| **国内未兴起型**(如 FDE) | TOP10 中 <3 家在招 **且** 平台独立雇主 <20 家 | **以湾区源为主**(公司官网/官方博客/JD),词条必须明示"该职业国内尚未形成招聘规模,以下主要参考美国湾区实践";入行层不得编造国内路径 |

TOP10 大厂参考名单(按市值/营收+规模化校招口径,**每年校招季更新一次并记录版本**;2026 版草案):字节跳动、腾讯、阿里、华为、美团、京东、拼多多、百度、网易、小米。

### 8.2 趋势/发展层的三方综合规则
trend 层与 development 层的前瞻性断言,须从三方源综合判定,**至少两方印证才可写入**(单方=降 null 或明确标注单一来源视角):
1. **硅谷/湾区**:技术前沿与岗位演化信号(公司官方博客/JD 变化/官方技术报告);
2. **大湾区**(深圳/广州/香港):国内落地前哨(大厂大湾区岗位/政策试点);
3. **国内政策**:部委与地方官方文件(如人社部新职业目录/行业规划)。

### 8.3 X(Twitter)双重验证规则(裁决 7 细化,替代"一律禁")
- X 帖子**单独**仍不可作任何 tier 的证据;
- **官网+X 双重验证可用**:当 X 内容(限公司/机构官方账号或可实名核验的当事人账号)与官方来源(官网/官方博客/公告)相互印证同一事实时,官网 URL 为主证据(tier 按官网定),X URL 写入 evidence 备注作佐证信号;
- 其余社媒(微博/小红书/抖音/贴吧)维持一律禁,无双重验证例外。

### 8.4 落点
本节条款编入 L1 通用骨架的「源基准」段与 L2 各档 source_priority 之上(定级判据先行);S1 族源池阶段第一步=对该职业跑成熟度定级并在源池文件头记录定级证据(几家在招/哪几家/检索日期)。
