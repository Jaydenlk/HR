# Skill: frontend-logic-design

## Purpose
Frontend logic design review and correction. Used when the UI feels "off", illogical, inconsistent, or when information hierarchy is confusing.

## Methodologies Applied

### MECE (Mutually Exclusive, Collectively Exhaustive)
- Every piece of information belongs to exactly one category
- No gaps in information coverage
- No overlapping categories that confuse users

### Progressive Disclosure
- Show only what's needed at each step
- Complexity revealed gradually as user needs it
- Don't overwhelm with all options at once

### Shneiderman's 8 Golden Rules
1. Strive for consistency
2. Enable frequent users to use shortcuts
3. Offer informative feedback
4. Design dialogs to yield closure
5. Offer simple error handling
6. Permit easy reversal of actions
7. Support internal locus of control
8. Reduce short-term memory load

## When to Trigger
- User says the interface "doesn't feel right" (不对劲)
- Information hierarchy seems confused (信息层级混乱)
- Interactions are inconsistent (交互不一致)
- Navigation doesn't follow user mental model
- Too much or too little information on a page

## Output
- Systematic diagnosis of what's wrong
- Specific corrections with rationale
- Before/after comparison when applicable
