# 支付与域名备案档案(Coach 商业化前置准备)

> 性质:**准备文档**,对应路线图 P1(域名/备案)与 P2(收费试水)。写于 2026-06,政策类条目办理时以官方页面为准。
> 结论先行:**备案周期 1-4 周且是一切的前置,应最先启动**;支付主体(个体工商户)第二;支付模块代码最后写。

---

## 1. 总路径图

```
买域名(实名) → ICP备案(1-4周) → 公安备案(30天内) → 服务器开443+Caddy自动HTTPS
                                                      ↓
        注册个体工商户(约1-2周,可与备案并行) → 微信/支付宝商户号 → 支付模块开发 → 收费试水
```

两条线可以并行,总等待期约 2-4 周——这就是为什么 8 月秋招窗口要倒推,6-7 月就得启动。

---

## 2. 域名与 ICP 备案

### 2.1 买域名
- 在国内大厂买(阿里云/腾讯云),**必须实名认证,且实名主体要与后续备案主体一致**(个人备案=个人实名;个体工商户备案=经营者实名)。
- 选 `.com`/`.cn` 等常规后缀,别选不支持备案的小众后缀。

### 2.2 备案类型选择(关键决策)
- **个人备案**:免费、材料最简,但**网站定性为非经营性,不可用于商业用途**。Coach 免费试运行阶段勉强可用,一旦收费就不合规。
- **企业类备案(以个体工商户/公司为主体)**:商业化的正路。需营业执照。
- **经营性 ICP 许可证**(在备案号之上再办):法规上"经营性互联网信息服务"需要它,但门槛是公司主体+注册资本 100 万(认缴)+年审,**绝大多数独立开发者起步阶段不办,属普遍存在的合规灰区**。建议:个体工商户主体先跑,收入成规模或渠道审查要求时再升级公司主体补办。这是风险自担的现实选择,记录在此,拍板权在你。

### 2.3 备案流程(在服务器所在云厂商的备案系统提交)
1. 准备:身份证、手机号(短信核验)、服务器备案服务码(云厂商控制台领取)、网站名称(别带"AI/平台/中国"等敏感词,通过率高的写法如"Coach 求职辅导工具")。
2. 提交 → 云厂商初审(1-2 天)→ 省管局审核(各省 1-20 个工作日不等)→ 下发备案号。
3. **备案期间域名不能解析到服务器**(部分省份要求关站),所以要趁试运行用 IP 访问的现在办,无感。
4. 备案号下来后 30 天内做**公安联网备案**(全国互联网安全管理服务平台),页脚挂两个备案号。

### 2.4 备案通过后 Coach 侧动作(半天内完成)
1. 域名 A 记录解析到服务器 IP
2. 安全组开 443(TCP)
3. `/opt/coach/.env.production`:`DOMAIN=域名`、`CORS_ORIGINS=https://域名`
4. `docker compose ... up -d caddy api` —— Caddy 自动签 HTTPS 证书
5. 页脚加备案号组件(工信部备案号需链接到 beian.miit.gov.cn)
6. 验证:`https://域名/api/health` 外网 200、证书有效、http 自动跳 https

## 3. 支付主体与商户号

### 3.1 三档方案(按规模递进)

| 档位 | 做法 | 适用 | 风险/成本 |
|------|------|------|----------|
| 手动档 | 个人收款码收款 + 管理后台手动给用户开权限 | 试水期(≤几十单),验证"有没有人肯付钱" | 无开发成本;个人码用于经营有政策边界,小规模过渡可接受 |
| 标准档 | **个体工商户 + 微信/支付宝商户号 + 自动化支付模块** | 验证付费意愿后的正式方案 | 注册个体户成本低(代办几百元,1-2 周);费率约 0.6%(以签约页为准) |
| 合规档 | 公司主体 + 经营性 ICP 证 | 收入成规模后 | 注册资本认缴 100 万 + 年审,起步不碰 |

**建议:先手动档验证付费意愿(零开发),同时注册个体工商户;有 10 单真实付费再写支付模块。**——这本身就是减法原则。

### 3.2 个体工商户路线要点
- 注册:经营范围写"软件开发;信息技术咨询"类;可线上代办。拿到营业执照后办对公或用经营者银行卡(微信支付支持个体户用经营者个人卡结算)。
- **微信支付**:商户平台申请商户号(材料:营业执照彩色扫描件+经营者身份证+结算银行卡)。PC 网站收款用 **Native 支付(扫码)**,要求网站已 ICP 备案且与主体一致。注:若日后做小程序才需要每年 300 元微信认证,纯网站扫码不需要。
- **支付宝**:开企业支付宝账户(个体户可开)→ 签约"电脑网站支付"。
- 两家都要求**HTTPS 域名回调地址**——所以备案+HTTPS 是支付的硬前置。

## 4. Coach 支付模块技术设计草案(P2 时再实现,现在只立约束)

商业模型(已拍板方向):**校招季单次付费 99-199 元,买断诊断+改写权益**(非订阅,符合校招人群的一次性场景)。

设计约束(开发时按此走,防止做歪):
- 新模块 `packages/api/src/payments/`:orders 实体(订单号/用户/金额/渠道/状态机 created→paid→refunded)+ 渠道适配器(先微信 Native,后支付宝,同一接口)
- **回调三铁律**:验签(拒绝伪造回调)、幂等(同一单重复回调只生效一次)、金额复核(回调金额必须等于订单金额,不信任客户端)
- 支付成功 → 解锁用户权益字段(如 `paid_until` 或次数包),quota 模块读它放行
- 对账:管理后台加订单列表 + 每日对账数(订单表 vs 渠道账单),对不上要报警
- 退款政策先写进用户条款再上线收费(AI 服务的退款边界要提前说清,如"已消耗诊断次数不退")
- 沙箱先行:微信/支付宝都有沙箱环境,支付模块全部用沙箱过 e2e 后才碰真实商户号
- 密钥纪律照旧:商户密钥/证书只进 `.env.production` 与服务器,永不入库

## 5. 启动时间线建议(对齐 8 月秋招窗口)

| 时间 | 动作 | 负责 |
|------|------|------|
| 现在 | 拍板域名名称并购买、确认备案主体(个人先备 or 直接个体户) | 你 |
| 本月 | 提交 ICP 备案;(若走商业化)并行注册个体工商户 | 你提交,材料清单见上 |
| 备案下发后 | 域名切换+HTTPS+页脚备案号(半天) | AI 执行,流程见 §2.4 |
| 试运行有付费意愿信号 | 手动档收款验证 → 申请商户号 | 你 |
| P2 | 支付模块开发(按 §4 约束) | AI 执行 |
