# 0→1 快速落地方法论(产品人 × AI 团队协作手册)

> 读者:你(产品负责人,不写代码)。写于 2026-06,方法全部在 Coach 项目上验证过。
> 一句话总纲:**0→1 的效率不取决于 AI 写代码多快,取决于"想法 → 可验证反馈"这个循环转多快。**
> 你的全部工作就是让这个循环转得快、转得真。

---

## 1. 五段律(0→1 的标准节奏)

```
①想清楚(半天~1天) → ②环境先行(1天) → ③骨架(2-3天) → ④迭代环(主体时间) → ⑤上线见真人(越早越好)
```

- **①想清楚**:产出一页纸 PRD(模板见 §2)。这一步省掉的每个小时,后面要用十个小时返工还。
- **②环境先行**:第一行业务代码之前,先让 AI 搭好"它能自己验证自己"的环境——测试框架、lint、E2E、health 接口、一键启动脚本。**可验证性是效率的放大器**:AI 能自测,你就不用当人肉测试机,循环就不经过你。
- **③骨架**:走通一条最细的端到端链路(登录→核心动作→看到结果),宁可丑但要通。骨架通了,后面所有功能都是往骨架上挂肉,可以并行。
- **④迭代环**:见 §4 的双环模型,这是日常主体。
- **⑤上线**:第一批真用户的反馈价值超过你自己一百次预想。上线前彩排(本机原样跑一遍生产流程),上线后立刻外部视角验证。**别憋大招**——Coach 砍掉一半功能先上线,是这个项目做对的最重要决定之一。

---

## 2. PRD 怎么写给 AI(一页纸模板)

AI 时代 PRD 的唯一目的:**让 AI 不用猜**。猜 = 返工 = 最大的效率黑洞。

```
【用户是谁】一句话画像 + 他此刻的处境
【要解决什么】用户用人话说出来的那个痛(不是你想做的功能)
【业务链路】入口 → 每一步用户看到什么/做什么/系统给什么 → 出口(用户带着什么离开)
            ★这是全文档最重要的一段,逐环节写,它就是日后验收的唯一基准
【成功长什么样】用户视角的 2-3 条可观察标准(不是"体验好",是"30秒内拿到诊断结果且能看懂")
【不做清单】明确砍掉的东西 + 为什么(没有这段,AI 一定帮你把功能堆回来)
【红线】绝不能发生的事(如:AI 不许编造、不许出现假数据、密钥不入库)
【数据与边界】真实数据从哪来;空数据/坏数据/超量数据时应该发生什么
```

两个关键心法:
- **写"什么",不写"怎么"**。技术方案让 AI 提、让 AI 对比、你来拍板。你写技术方案 = 用你的短板去锁死 AI 的长板。
- **业务链路写到"按钮级"**。"用户上传简历后开始诊断"太粗;"用户拖入 PDF→看到解析进度→解析完自动跳转预览页→点'开始诊断'按钮"才够细。链路写多细,验收就能多严。

## 3. Agentic Engineering 四大支柱

1. **把 AI 当团队,不当工具**。一个主代理当工程经理(分解/派工/质检/集成),多个子代理当工程师(实现/测试/审计)。关键铁律:**实现、测试、审计必须是三个不同的 agent**(三权分立)——实现者自己说"测过了"永远不算数。这不是流程税,Coach 项目里审计真抓到过实现者虚报。
2. **可验证性先于功能**。每个功能的定义里就包含"怎么证明它对":step→verify 格式(每步一个动作+一个可独立运行的检查)。AI 的特性是:**你能验证什么,它就能做好什么;你验证不了的,它就会糊弄**(不是恶意,是它收不到纠偏信号)。
3. **文档即记忆**。AI 没有跨会话记忆,所以项目要有三层外置大脑:CLAUDE.md(性格与红线,每次自动加载)→ 方法论文档(FABLE-PLAYBOOK)→ 操作手册+断点记忆(AGENT-HANDBOOK + 记忆文件)。**手册不更新,经验就随会话蒸发**。每次大任务收尾让 AI 自己写交接。
4. **红线前置**。把"绝不能发生的事"写在所有提示词最前面并反复出现(防编造/无 mock/无空按钮/密钥不入库)。红线的特点是:违反一次的代价 >> 一百次重申的成本。

## 4. Loop 设计(双环模型——人机分工的核心)

```
内环(AI 自循环,不经过你):  派工 → 实现 → 自测 → 独立审计 → 集成 → 提交
外环(你介入的环):          定方向/写PRD → [内环跑若干圈] → 你验收 → 给反馈/拍板 → 下一轮
```

效率的关键就一条:**人不进内环**。

- 你在内环里出现一次(中途问"行不行""要不要继续"),AI 就停一次,循环就断一次。授权写清楚("全部同意,不用问"),让内环全速转。
- 你的价值全部在外环:**方向**(要什么、更重要的是不要什么)、**拍板**(不可逆决策:花钱/删数据/对外发布/架构选型)、**验收**(用真实用户的手和眼,真点真用,不看 AI 的总结)。
- 内环要自带刹车,不然会空转烧钱:同一思路失败 3 次换路、8 次熔断上报、连续 2 轮无新发现收队。这些已写进 CLAUDE.md,你不用管,但要知道它们存在——AI 长时间没动静时,先问"是不是熔断了",而不是加一句"快点"。

## 5. Prompt 四件套的正确用法(`docs/PROMPTS.md`)

| 哪份 | 何时用 | 你要做的 |
|------|--------|---------|
| A 任务总控 | 每个开发任务贴一次 | 只填【需求】三行:业务链路写到按钮级、不做清单别空着 |
| B 开发原则 | 常驻(已进 CLAUDE.md) | 不用动 |
| C 前端验收 | 常驻 | 验收报告回来时,抽查"已走流程清单"是否真覆盖 |
| D 后端验收 | 常驻 | AI 接口必看"防编造测试"那条的证据 |

三个加速口令(在本项目环境下):
- **"ultracode"** = 授权大编队,多 agent 并行+对抗验证,适合大任务/审计/调研,烧 token 换质量和速度。
- **任务开头给授权边界**:"全部同意不用问,但 X 之前要问我" —— 一句话让内环不断。
- **要求"先彩排再上生产"**:凡是第一次碰生产环境的动作,这五个字能避开 90% 的上线事故。

## 6. 人机协作十条(我认为你最需要知道的)

1. **你只握三样:方向、拍板、验收**。其余一切(包括技术选型的调研、方案对比)都可以让 AI 做,但这三样让渡出去,产品就不是你的了。
2. **反馈要可裁决**。"不好看"AI 没法执行;"这个页面的数字是编的,改成公测口径"立刻能修。把感受翻译成【场景+现状+期望】三段,一次反馈一次到位。
3. **给真实弹药**。真简历、真服务器、真密钥(走安全渠道)、真用户反馈。AI 能编出一切看起来对的东西,唯独编不出真实——Coach 的好几个真 bug 都是真数据喂出来的。
4. **别中途夺方向盘**。你手动改了代码/服务器/配置,必须告诉 AI,否则它的世界观就错位了,后面全是诡异 bug。最好的分工:动手的事全让 AI 做,它做不了的(贴公钥/扫码/收验证码)它会教你做哪两步。
5. **信任但抽查**。AI 报"全部通过"时,随机抽一条要原始证据(测试输出/截图)。抽查的存在本身就会改变 AI 的行为——这正是验收标准里"零 bug 报告默认不可信"的原理。
6. **一个会话一个主题**。大任务开新会话并让 AI 先读交接文档;杂事别混进开发会话。上下文越干净,AI 越聪明。
7. **逼 AI 记录决策**。每个重要选择(选了什么/排除了什么/为什么)落盘。不记录的代价是:三周后它(或下一个模型)把你们否决过的方案重新发明一遍。
8. **减法权在你手里,而且只在你手里**。AI 的天性是顺着你加功能(它没有"拒绝老板"的本能)。"这个功能砍掉"是 AI 永远不会主动说、但产品最需要听到的话。定期问 AI:"如果必须砍掉三个功能,砍哪三个?"——它分析得很好,只是不会主动提。
9. **付钱的节奏**:小任务单兵(便宜),不确定性高/可并行/要对抗验证的任务才开编队(贵但值)。判断标准:这个任务做错的代价,是否高于编队多花的钱。
10. **AI 的报告永远比现实乐观一档**。这不是骗,是它的训练偏好。对策已内置(证据文化/独立审计/找茬验收),但你心里要有这个系数:看到"基本完成"读作"还有硬骨头",看到"全部通过"读作"主流程通过"。

## 7. 常见翻车模式速查(全部在本项目真实发生过 → 解药)

| 翻车模式 | 解药(已制度化在哪) |
|----------|----------------|
| AI 说"完成了"但功能是空的(空按钮/假数据) | 证据文化 + Playwright 真点 → PROMPTS.md C |
| 编译通过被当成测试通过 | "tsc 不是 lint,真跑才算" → CLAUDE.md 行为内核 |
| 为过验收打补丁,代码越打越烂 | 根因修复红线 + Simplify 审查 → PROMPTS.md B-6 |
| 功能越堆越多,核心越做越薄 | 不做清单 + 减法权在人 → 本文 §2/§6-8 |
| AI 卡死在一个问题上反复重试烧钱 | 3次换路/8次熔断 → CLAUDE.md |
| 换模型/换会话后水准断崖 | 三层外置大脑 + 交接文档 → 本文 §3-3 |
| 第一次上生产就翻车 | 彩排法则 → FABLE-PLAYBOOK §2 |

## 8. 新项目 Day 0 检查单(下次 0→1 直接照抄)

```
□ 一页纸 PRD(§2 模板),重点打磨业务链路和不做清单
□ 建仓库,把四件套带过去:CLAUDE.md(行为内核+红线)/ PROMPTS.md / FABLE-PLAYBOOK.md / 空的 HANDBOOK
□ 第一个任务永远是"环境先行":测试框架+lint+E2E+health+一键启动,AI 自己能转才开工
□ 授权边界一句话说清:"全部同意不用问,除了 ___"
□ 定好节奏:每个迭代环收尾 = 全门禁 + 你真手验收一次 + 决策落盘
□ 最迟第二周末:上线给真人用,哪怕只有三个用户
```
