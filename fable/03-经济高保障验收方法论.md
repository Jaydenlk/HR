# 经济高保障验收方法论(可移植版)

> 配套《防降智保险方法论》。回答一个问题:**执行者会降智、token 有预算,怎么在不烧钱的前提下让验收真拦得住问题?**
> 核心命题:经济和保障不是折中,是**排序**——便宜的闸放前面挡掉大多数问题,贵的火力(强模型/人工)只砸在真会出错的少数地方。乱序才贵:用 LLM 去数字符、每条都上最重审查、为凑发现报鸡毛蒜皮,那是既贵又没保障。
> 全文规则带真实事故背书,反面案例保留。

---

## 一、总原则:验收金字塔(从便宜到贵,逐层过滤)

一次验收 = 四层漏斗,**下层只处理上层漏下来的**。绝大多数问题在最便宜的两层就被拦掉,越贵的层处理的量越少。

```
第4层  人工/强模型拍板     ← 最贵，只碰不可逆决策和高危疑点   (每任务 0-1 次)
第3层  对抗式审计(强模型) ← 贵，只审"合并 diff"和高危字段     (每任务 1 次，轻量)
第2层  语义审查(中档模型) ← 中，只看确定性脚本判不了的         (按需)
第1层  确定性脚本 + 编译/lint/测试 ← 免费或近免费，先跑，挡掉 80%  (每次必跑)
```

**为什么这样最省又最稳**:
- 第 1 层是纯计算(字段完整度、黑名单、残留 grep、类型检查、测试真跑),**比任何 LLM 都便宜且更可靠**——它测的东西本就是确定性的。80% 的问题(漏改、编译错、残留、断言挂)在这层暴露,根本轮不到花钱的层。
- 越往上,处理的条目越少、单条越贵。把贵的火力留给"确定性手段判不了的语义问题"和"真出过事故的高危点"。
- **反例(乱序的代价)**:早期我们让 LLM 去检查"词汇密度/套话黑名单/字段齐不齐"——这些是纯字符串计数,LLM 又慢又贵又不稳,还不如 30 行脚本。把它们下沉到脚本后,单位验收成本掉了一个量级,质量反而升了。

---

## 二、第 1 层:确定性闸(免费,必跑,放最前)

**这层的任务:用零成本手段挡掉尽可能多的问题,给贵的层减负。**

| 闸 | 手段 | 拦什么 |
|----|------|--------|
| 编译探针 | `tsc --noEmit` / 等价 | 悬空引用、类型错(**注意:这不是测试,只是探针**) |
| Lint | `eslint` 0 错 | 风格/低级错 |
| 单元测试 | 真跑,附统计行 | 逻辑回归 |
| e2e/集成 | 真跑,**用对命令**(见下) | 端到端回归 |
| 残留扫描 | `grep` 关键符号,核对白名单 | 删除/重构没删干净 |
| 完整度/黑名单 | 脚本数字段、查禁用词 | 漏填、套话、格式违规 |

**铁律**:
1. **概念不许偷换**:编译通过 ≠ lint 通过 ≠ 测试通过。三件事分别验、分别给证据。
2. **命令即证据(防假绿)**:声称"测试过"的证据必须来自那条**参数正确**的命令的原始输出。真实事故:e2e 文件以 `-spec.ts` 结尾,裸 jest 的 testRegex 只匹配 `.spec.ts`,裸跑会 **0 匹配、静默跳过全部 e2e、报"全部通过"**——最核心的验收用例一条没跑却绿灯。**把每条命令的正确参数、该在哪个目录跑、为什么,写进纪律文档,并注明"别改回去"。**
3. **基线先绿**:存量恒红的测试必须先修绿或显式隔离,否则"允许失败数"说不清,判据直接失真。我们有 4 条 e2e 因"种子写死某季度、系统按当前季度过滤"恒红——不清掉,执行者永远分不清"我改坏的"还是"本来红的"。**开工第一件事就是清基线,然后规定允许失败数=0,不留"已知失败白名单"给执行者自由心证。**

## 三、第 2-3 层:LLM 审查(花钱的层,精准投放)

### 只在这些地方花钱

- **确定性脚本判不了的语义问题**:可核实性、逻辑对不对、"是不是在编造/是不是只说好话"、换个名字能不能区分。
- **高危字段**:具体数字、规范/阈值、跨场景的具体差异、安全相关改动、不可逆操作附近的代码。
- 低危字段(一句话简介、产出物清单)轻检即过,不值得上重审查。

### 三个省钱又保质的关键手法

**① 风险分级,火力集中**
不是每条都上同等强度审查。低危送分项一笔带过,把对抗式审查全压在"真会出错"的高危字段上——省钱的同时火力更集中。

**② 断言级检查,不搞整体重写**
质量来自**对每一条具体断言的检查**(这条陈述有没有来源支撑),不来自审查遍数。
- 真实事故:早期一版流水线,7-8 轮审查结果反而更差——因为修复方式是"整条重写",每轮改掉旧错的同时引入新错,永不收敛。
- 正解:审查发现问题必须**点名到具体字段**,只定点补那几个字段,**封顶 1-2 轮,永不整条重建**。修不好就搁置进人工队列,不无限烧。

**③ 合并后对抗式审计:一次,轻量,不通胀**
代码合并进主干后,加**一个**审计代理(强模型、对抗立场),只审"合并这个动作引入的问题":冲突解错、半合并、红线触碰、与既有代码的相互作用。
- **"保证没问题即收工"**:没有实质问题就一句"未发现",**明令禁止为显得认真而报鸡毛蒜皮凑数**——审计通胀既烧 token 又制造噪音淹没真问题。
- 判据:发现 blocking → 立即小修或回滚;只有 minor → 记录放行。

## 四、判据机械化(让弱模型只对表,不理解)

验收结果必须**结构化、可布尔判定**,执行者做"对表"不做"解释"——这是经济性和防降智的交汇点:机械判定不需要智力,也就不怕降智。

**结构化返回**:
```
测试代理 → { gates:[{name, pass, evidence}], overall_pass: bool }
审计代理 → { verdict: "PASS"|"FAIL", findings:[{severity, file, issue, evidence}] }
```

**通过判据(硬条件,缺一不合并)**:
- `overall_pass === true`(全部适用质量门绿)
- e2e/Playwright 等**适用门真跑真过**;纯后端任务 Playwright 记 N/A 但**必须写明 N/A 理由**(不写=可能是偷懒跳过)
- 审计 `verdict === PASS` 且无 `blocking`
- 残留扫描符合白名单

**严重度裁决规则(写死,不临场解释)**:
- `blocking`:必须清零才合并。
- `major`:记入遗留清单,不阻断;但**同类累计 ≥3 升级为必修**(防温水煮青蛙)。
- `minor`:只记录。

**为什么机械化 = 经济**:解释权一旦交给执行者,弱模型要么放水(该拦的没拦,后期返工更贵)、要么通胀(过度审查烧 token)。写死判据把这两种浪费同时掐掉。

---

## 五、修复循环:有界,不无底洞

**做法**:
1. 从质量门/审计里摘出所有 FAIL 项和 blocking 发现,**原样带 evidence**。
2. 派修复代理,prompt = 原任务红线 + 这批具体失败项 + "只修这些,不扩范围,修完复跑失败的那几门附输出"。
3. 复验:**只重跑失败的门**(用编排的缓存/断点能力跳过已过的门,别全量重跑——这是省钱点)。
4. **修复最多 2 轮**;仍不过 → STOP,写清卡点等人。

**踩过的坑**:不设上限的修复循环 = token 无底洞,还常常越修越乱。2 轮封顶 + STOP 协议,把"烧钱空转"变成"及时止损交人"。

## 六、反优绩主义:每道闸自证价值

**这是经济性的总闸门:不产生保障的验收动作,一律砍掉。**

- 所有流程指标(审查轮数、检查项数、门数)**都不是目标本身**,产出对不对才是。
- **试点批统计**:每道质量闸在小规模试点里统计"抓到过几个真问题"。一道闸如果一个真错都没抓到,量产时**直接砍掉**——它只在烧钱。
- 验收北极星是"对真实使用者有没有用",不是"流程分多高"。
- 反例:曾有一版验收堆了七八道闸,看着严谨,实测大半从没抓到过真问题,纯烧 token+制造仪式感。砍到只剩"防编造死线 + 断言级检查"两道硬闸后,又快又准。

**一个可盯的单一指标**:每单位合格产出的 token 成本。它同时反映经济性(分母花了多少)和保障(分子是不是真合格)。这个数异常上涨,不是要加闸,是要查哪道闸在空转。

## 七、落到 PRD:验收部分怎么写

- [ ] **每个需求配可执行验收**:命令/操作 + 期望输出。写不出验证方式的需求 = 没想清楚,打回。
- [ ] **验收分层标注**:哪些验收项是脚本能判的(第1层)、哪些必须人/强模型看(第3-4层)——PRD 阶段就分好,执行期照做。
- [ ] **高危清单**:列出"改动即高危"的模块/字段(安全、支付、不可逆操作、出过事故的代码),规定它们享受最重验收(对抗审查+人工复核)。
- [ ] **基线绿色作为开工前置**:第一个功能开工前,测试基线全绿、lint 零错、验收命令跑通,写成开工 checklist 第一项。
- [ ] **命令陷阱备忘**:项目里凡"跑测试要用特定参数/目录"的坑,写进纪律文档,附"为什么、别改回去"。
- [ ] **修复循环上限**:写死"最多 N 轮,不过即 STOP",别留无底洞。
- [ ] **审计不通胀条款**:明文规定"保证没问题即收工,禁止为凑数报琐碎发现"。

---

## 八、一句话总结

**便宜的闸放前面挡掉大多数,贵的火力只砸在真会出错的地方;判据写成机器能对的表,修复设上限,每道闸都得自证抓过真错。**

省钱不是少验,是**把验收按成本排好序、把火力投准**——乱序和通胀才是真浪费。
